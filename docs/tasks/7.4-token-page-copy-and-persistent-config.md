# 7.4 令牌页：复制按钮在 http 下可用，接入命令一次配置永久生效

不新增依赖、不改迁移。

## 问题（用户在线上验收时发现）

1. 线上地址是 `http://192.168.11.85:32441`，不是 https 也不是 localhost，浏览器在这种情况下不提供 `navigator.clipboard`，所以「复制」「复制 Claude Code 命令」「复制 Codex 命令」三个按钮全部失效。
2. Codex 的接入命令依赖 `export RUYI_TOKEN=...`，换一个终端窗口就失效。用户要求：**执行一次后，以后不用再配置。**

## 修改要求

### 1. 复制功能兼容 http（`apps/web/src/views/ApiTokensView.vue`）

- 新增通用函数 `copyText(text)`，可放在 `apps/web/src/` 下的小工具文件里：
  - 优先 `navigator.clipboard?.writeText`（仅在 `window.isSecureContext` 为真时使用）；
  - 否则回退：创建临时 `<textarea readonly>`，放到屏幕外（`position: fixed; top: -1000px`），写入内容，`select()` 后执行 `document.execCommand('copy')`，最后移除节点；返回是否成功；
  - 两种方式都失败时返回 false。
- 三个复制按钮都改用 `copyText`。
- 失败时的提示改为：「浏览器不允许自动复制，请选中下方文字后按 ⌘C / Ctrl+C 复制」。同时把对应文本框自动选中，方便用户直接复制：命令和令牌都放在只读 `<textarea>` 里，或者使用可选中的元素。

### 2. 接入命令改为“一次配置、永久生效”

**Claude Code**（`--scope user` 本身已经永久保存，只需要让它可以重复执行）：
```sh
claude mcp remove ruyi --scope user 2>/dev/null; claude mcp add --transport http --scope user ruyi '<平台地址>/mcp' --header 'Authorization: Bearer <令牌>'
```
先删再加，换令牌时重新执行同一条命令即可，不会报“已存在”。

**Codex**：不再使用环境变量，直接把令牌写进 Codex 的用户配置 `~/.codex/config.toml`。Claude 已验证 Codex 支持在配置中写固定请求头 `http_headers`，`codex mcp list` 中显示为 `Bearer token`。生成如下 shell 命令（POSIX sh，macOS / Linux 通用）：
```sh
codex mcp remove ruyi 2>/dev/null; mkdir -p ~/.codex && printf '\n[mcp_servers.ruyi]\nurl = "%s"\nhttp_headers = { Authorization = "Bearer %s" }\n' '<平台地址>/mcp' '<令牌>' >> ~/.codex/config.toml && chmod 600 ~/.codex/config.toml
```
- 平台地址取 `window.location.origin`，沿用现有的 `shellQuote` 处理单引号。令牌字符集是 base64url，不含引号。
- 页面上未生成令牌时显示 `<令牌>` 占位；刚生成令牌后，复制按钮复制的是带真实令牌的完整命令。现有行为不变，只是改了命令内容。
- 页面说明文字：
  - 删除「启动 Codex 的终端环境中也必须设置 RUYI_TOKEN」；
  - 改为「命令只需执行一次，配置会永久保存在本机；令牌到期或吊销后，生成新令牌并重新执行同一条命令即可。」
  - 补充「检查是否接入成功：`claude mcp list` 或 `codex mcp list` 中出现 ruyi」。
- Skill 安装命令也给出可直接复制的完整命令，一次即可：
  ```sh
  mkdir -p ~/.claude/skills && unzip -o ~/Downloads/ruyi-audience.zip -d ~/.claude/skills/
  ```
  Codex 版本把 `.claude` 换成 `.codex`。各配一个复制按钮，不需要令牌，始终可复制。

### 3. 文档

`docs/MCP_USAGE.md` 中的 Claude Code 和 Codex 接入步骤与页面保持一致：Codex 改为写入 `config.toml`，删除 `RUYI_TOKEN` 相关说明，补充“换令牌时重新执行同一条命令”。

### 4. 测试（`test/frontend-api-tokens.test.js`）

- `copyText`：`isSecureContext=false` 且无 `navigator.clipboard` 时走 `execCommand` 回退，并返回 true；回退也失败时返回 false，页面显示新的失败提示。
- 生成令牌后，Claude Code 命令以 `claude mcp remove ruyi --scope user` 开头、包含 `--scope user` 和真实令牌；Codex 命令包含 `http_headers = { Authorization = "Bearer <真实令牌>" }` 和 `chmod 600`，**不包含** `RUYI_TOKEN`。
- 未生成令牌时，命令中是 `<令牌>` 占位。
