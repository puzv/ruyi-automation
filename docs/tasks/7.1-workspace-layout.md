# 7.1 apps/packages 目录与模块边界迁移

## 目标与负责人确认
负责人确认采用最初规划的 apps/packages 分层，继续 CommonJS JavaScript（Vue 为 ESM）、Kysely、现有路由。不要同时迁移 TypeScript、Pinia、vue-router，不做自动化纯函数大改造。部署保持独立仓库。主代理统筹及验收，6.1 sol 子代理实施。

## 目录与边界
- web/ → apps/web/，完整保留前端源码与构建配置；package.json 使用 @ruyi/web。
- server/ 中 API 专属代码 → apps/server/src/；启动入口 main.js，模块按 auth、audit、files、jobs、platform-login 等实际业务分组（不强行制造空目录）。认证/错误处理等跨模块设施可放 plugins/，保持现有公共 API 行为。
- server/worker/ → apps/worker/src/，启动 main.js；保留默认内嵌及独立启动两种方式。
- 根自动化 move/upload/uploadAll/createGroup/createAllGroup/analyse/analyseAll/download/downloadAll 与浏览器、文件、登录等 lib → packages/automation/。可保留原 .js 文件名，避免与目录整理无关的改名。
- config.js、macos-arch、playwright-env 与纯根路径定位 → packages/shared/；shared/runtime 放 API/Worker 确实共用的仓储、审计、workspace、platform-state。只有 API 使用的会话仓储/鉴权留 API。shared 不依赖 automation 或 apps，worker 不依赖 server；server 可单向组合 worker，兼容测试内存执行可引用其 execution 子入口。
- 根 db/ 保留，尤其 db/migrations/ 的既有内容与路径均不得修改；scripts/ 保留运维脚本与 job-wrapper；test/、docs/ 保留。
- 根 package.json 加 workspaces（apps/*、packages/*），各包 private:true，声明实际依赖。根 npm start、worker、build:web、dev:*、自动化命令、全部测试命令继续有效。统一根 package-lock.json；迁走旧 web lockfile 的删除属于本任务明确允许的依赖清单整理，依赖版本以既有锁为基准，不升级依赖、不引入新第三方依赖。

## 数据、路径和现有工作
- .env、state-test.json、*.state.json、ruyi-profile、upload、.playwright-browsers 都原地保留；不读取数据。projectRoot 明确仍指仓库根，不受 cwd 和各 workspace 运行目录影响；默认数据/缓存路径、dotenv 加载位置保持。仅主代理 shasum 检查敏感文件。
- 先加载纯 paths 再按既有条件加载 .env，避免 shared 配置提前求值；测试不得因此加载真实 .env。
- 只移动明确列出的源码文件/目录，禁止扫描/搬动整个根或读取数据目录。允许为此次结构迁移移动/删除旧源码路径，禁止保留双份实现或大批旧路径转发壳。
- 当前注册、桌面协议修复、6.5 规模判断与测试以及其他既有未提交变更必须完整保留。不得触碰 upload/analyseToDoList.json 的既有修改。
- 子代理不可安装依赖、启动浏览器、改 lockfile、操作部署仓库、连接远程库、执行迁移、提交或开子代理。主代理负责安装/更新锁、浏览器验收与完整回归。

## 必须适配
- 所有 require/import/测试 VM 加载路径、静态 dist 目录、Worker scriptPaths、批处理子脚本路径、job-wrapper、测试 fixture、npm scripts、浏览器工具。
- 包子入口允许通过 workspace 名访问，共享模块不因单一总 index 产生意外初始化或循环。
- README.md、AGENTS.md 中当前目录及命令说明，REFACTOR_PLAN 技术决定和新增目录阶段状态；历史任务记录不批量改写。
- .gitignore 忽略所有 workspace node_modules，保留数据规则。
- 增加有意义的结构回归：非根 cwd 的默认根定位、Worker 子脚本/包装器解析、服务端静态文件路径、包依赖方向。不读取真实数据。

## 执行顺序与验收
1. 主代理完成 6.5 完整回归并通知后开始移动；此前只读准备。
2. 子代理迁移源码、package manifests、tests/docs，交主代理安装依赖并生成锁。
3. 主代理通知依赖就绪后，子代理跑专项并修复迁移遗漏。主代理亲读实际改动与移动清单，确认迁移文件内容 SHA-256、敏感文件 SHA1 不变，独立 npm run test:all、npm run build:web、浏览器冒烟及部署构建检查。
4. 部署适配独立任务 7.2，与应用代理文件边界严格分开。此阶段不自动推送镜像或操作线上集群；完成提供逐步验收清单并停下。
