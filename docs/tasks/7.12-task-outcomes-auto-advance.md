# 7.12 统一任务退出码与自动推进结果校验

## 背景与目标

线上上传日志显示 26 个文件进入创建清单，但自动创建任务约 1 秒即显示成功且没有日志。修复能从代码复现的假成功及推进停滞，明确不能仅凭退出码 0 宣称业务完成；不以本地修复冒充已确认线上空日志的根因。

## 范围

- 统一自动化四阶段及子脚本退出码：0 完成（空待办允许明确记录无操作），1 执行失败/不确定提交结果/协议异常，2 平台暂未就绪或部分未完成；取消与信号退出由 Worker 独立记录，不转换为成功。
- 创建、洞悉、上传、下载聚合脚本必须传播子脚本失败/未就绪，检查待办真实进展，避免无限循环和未完成却输出完成。仅平台明确接受提交后才能推进本地清单；提交结果不确定不得自动重复提交。
- 创建和洞悉提交以对应 POST 响应的 HTTP/业务成功为依据，拒绝、超时、无效 JSON 不更新清单。人群规模不足按既有明确跳过策略记录日志，不伪造洞悉结果。
- Worker 写入启动和结束摘要，检查已结束阶段的待办/成果后置条件，退出码与最终状态一致；缺失日志不再被静默混淆为脚本没有输出，保留用户隔离。
- 自动推进读取前次自动任务实际状态：未就绪可受限重试；普通失败/无进展成功/取消/中断保守停止并解释；排队和运行中不重复提交。保留开关竞态保护、近期关联任务、待办签名、默认 5 分钟间隔与不自动下载。
- 平台文件检查等待目标搜索响应及新结果，避免固定 800ms 读取旧表。
- 不新增依赖、不改数据库结构、部署、UI 设计、既有检测人群状态规则或用户数据；不提交或推送镜像。

## 实施分工

- 自动化子代理：shared 退出码契约、automation 阶段脚本、平台提交验证及相应测试。
- Worker/引擎子代理：Worker 后置校验和日志、任务查询日志诊断、自动推进重试/停止机制及相应测试。与自动化子代理共用 shared 契约，不修改其拥有文件。
- 主代理：检查每个实际改动文件和预存变更边界，独立验收。子代理均不得启动 Chromium，不得读取敏感文件或连接远程数据库。

## 验证与完成标准

- Node assert 行为测试覆盖四阶段 0/1/2、子进程信号/启动失败、空清单、无进展、部分完成、拒绝/超时/无效响应后不推进清单。
- 自动推进覆盖前次成功无进展、失败、未就绪后恢复、重试上限、取消、旧签名与新批次、运行任务防重、关闭竞态。
- 主代理重跑 npm test、npm run test:all、git diff --check；数据库测试仅本机 ruyi_test，不执行迁移。
- 使用临时假工作区/假登录态；禁止读取 .env、state-test.json、*.state.json、ruyi-profile/、upload/ 中真实数据。不得为计算摘要而违反禁止读取要求，采用只对授权代码的 diff/状态核对。
- 交付退出码说明、验证结果与线上逐步验收清单，等待用户验收，不自动发布。
