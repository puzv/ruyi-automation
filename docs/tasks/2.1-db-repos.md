# 任务 2.1：数据访问层与命令行创建管理员

先阅读 `AGENTS.md`、`docs/REFACTOR_PLAN.md`（重点看“阶段 2 的具体规则”），以及 `db/index.js`、`db/migrations/` 中的四张表定义。

## 本地环境（已准备好）
- 本机 Docker 中有 MySQL 5.7：`127.0.0.1:3306`，账号 `ruyi` / 密码 `ruyi`，开发库 `ruyi_dev`、测试库 `ruyi_test`，两个库都已执行完迁移（四张 `ruyi_` 表已存在）。
- 依赖 `bcryptjs@3`、`@fastify/cookie@11` 已安装，**不要再安装任何包**。
- 测试使用 `ruyi_test` 库，通过环境变量传入连接信息（不要读取 `.env` 文件）：`RUYI_DB_HOST=127.0.0.1 RUYI_DB_PORT=3306 RUYI_DB_USER=ruyi RUYI_DB_PASSWORD=ruyi RUYI_DB_NAME=ruyi_test`。

## 要做的事

### 1. `.env` 加载
- 新建 `db/env.js`，导出 `loadDotEnv(file)`：把 `scripts/migrate.js` 里的同名函数移过来（逻辑不变：`KEY=VALUE`，已存在的环境变量优先）。
- `scripts/migrate.js` 改为使用它；`server/index.js` 启动时加载项目根目录的 `.env`（文件不存在则跳过）。
- 不在 `db/index.js` 或测试中自动加载 `.env`。

### 2. 数据访问模块（`server/repos/`，每个文件导出接收 `db`（Kysely 实例）作为第一个参数的函数；全部用 Kysely 查询构建器或 `sql` 模板，禁止字符串拼接 SQL）
- `users.js`
  - `findByUsername(db, username)`、`findById(db, id)`
  - `createUser(db, { username, displayName, passwordHash, role, mustChangePassword, createdBy })` → 返回新 id
  - `listUsers(db)`：不返回 `password_hash`
  - `updatePassword(db, id, passwordHash, { mustChangePassword })`：同时写 `password_changed_at = NOW()`
  - `setStatus(db, id, status)`
  - `recordLoginFailure(db, id, { maxFailures, lockMinutes })`：失败次数加 1；达到上限时设置 `locked_until = NOW() + lockMinutes`，并把失败次数清零。要求单条 UPDATE 原子完成（用 SQL 表达式，不要先读后写）
  - `recordLoginSuccess(db, id, ip)`：清零失败次数、清空 `locked_until`，写 `last_login_at`、`last_login_ip`
- `sessions.js`
  - `createSession(db, { tokenHash, userId, ip, userAgent, expiresAt })`
  - `findActiveSession(db, tokenHash)`：返回会话及其用户（联表），只在 `revoked_at IS NULL AND expires_at > NOW()` 且用户 `status = 'active'` 时返回
  - `touchSession(db, tokenHash)`：更新 `last_seen_at = NOW()`
  - `revokeSession(db, tokenHash)`、`revokeUserSessions(db, userId, { exceptTokenHash })`
  - `deleteExpiredSessions(db, olderThanDays)`
- 时间一律使用数据库的 `NOW()`（连接已设为 `+08:00`），不要在 JS 中计算再写入，`expiresAt` 例外（由调用方传入 `Date`）。

### 3. 密码工具 `server/auth/password.js`
- `hashPassword(plain)`：bcryptjs，cost 12
- `verifyPassword(plain, hash)`
- `validatePasswordStrength(plain)`：至少 8 位，返回 `null` 或中文错误信息
- `validateUsername(name)`：`^[a-z0-9_]{3,32}$`，返回 `null` 或中文错误信息

### 4. 命令行工具 `scripts/create-admin.js`
- 用法：`node scripts/create-admin.js <用户名> [显示名]`
- 交互式输入两次密码（终端不回显），校验一致且符合强度；用户名已存在则报错退出
- 创建 `role='admin'`、`must_change_password=0` 的用户
- 写一条操作记录到 `ruyi_operation_logs`：`action='admin.user_create'`、`target_type='user'`、`target_id=<用户名>`、`result='success'`、`username` 填 `'cli'`、`user_id` 为空
- 启动时加载 `.env`；在根 `package.json` 增加 `"user:create-admin": "node scripts/create-admin.js"`
- 非终端环境（stdin 不是 TTY）时，允许通过环境变量 `RUYI_ADMIN_PASSWORD` 提供密码（便于自动化），否则报错退出

### 5. 测试 `test/db-repos.test.js`
- 只连接 `ruyi_test`；若环境变量 `RUYI_DB_NAME` 不是 `ruyi_test`，测试应直接报错退出，避免误连其他库
- 测试开始和结束时清空 `ruyi_user_sessions`、`ruyi_platform_states`、`ruyi_operation_logs`、`ruyi_users` 的数据（用 `DELETE`，注意外键顺序；禁止 TRUNCATE/DROP）
- 覆盖：创建与查找用户、`listUsers` 不含密码哈希、用户名唯一约束、中文显示名、`recordLoginFailure` 第 5 次时锁定且计数清零、`recordLoginSuccess` 清除锁定、会话创建/查找/过期不可见/撤销/停用用户后不可见、`revokeUserSessions` 保留指定会话、密码哈希与校验、用户名和密码校验规则
- 新增 npm 脚本 `"test:db": "RUYI_DB_HOST=127.0.0.1 RUYI_DB_PORT=3306 RUYI_DB_USER=ruyi RUYI_DB_PASSWORD=ruyi RUYI_DB_NAME=ruyi_test node test/db-repos.test.js"`；**不要**加进 `npm test`（`npm test` 必须在没有数据库时也能通过）
