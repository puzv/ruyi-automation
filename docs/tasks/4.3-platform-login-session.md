# 任务 4.3：服务端平台登录会话与登录检查

先阅读 `AGENTS.md`、`docs/REFACTOR_PLAN.md` 的“阶段 4 的具体决定”、`lib/storage-state.js`、`scripts/login-export-state.js`（已实测可用的登录导出流程）、`server/platform-state/`、`server/routes/platform-state.js`、`server/state.js`、`server/audit-actions.js`。

## 背景
平台（如翼、DataNexus）登录必须由真人扫码，所以服务端要启动一个**有头浏览器**让用户操作，等两个站点都登录成功后导出 storageState、加密入库。本任务只做服务端的“登录会话”状态机；画面如何显示给用户由 4.4（noVNC）解决。本机开发时有头浏览器直接出现在本机桌面上，所以本任务完成后在本机就能走通。

## 要做的事

### 1. 登录会话管理 `server/platform-login/sessions.js`
内存中维护登录会话（`Map`，键为会话 ID `randomUUID()`）。每个用户同时最多一个活动会话；全局最多 `RUYI_MAX_LOGIN_SESSIONS`（默认 2）个。

会话对象（内部）：`{ id, userId, username, status, sites: { ruyi: bool, datanexus: bool }, message, createdAt, lastActivityAt, browser, context, display }`。
`status` 取值：`starting` → `waiting`（等待用户登录）→ `saving` → `succeeded`；或 `failed` / `cancelled` / `expired`（超时）。

流程（参考 `scripts/login-export-state.js`，复用 `lib/storage-state.js` 的 `loginTargets`、`pageLooksLoggedIn`、`probeSite`）：
1. `startSession(user, { db, keys, log, launch })`：
   - 若用户已有活动会话，直接返回该会话（幂等）
   - 启动浏览器：`launch` 默认为 `chromium.launch({ headless: false, executablePath: chromePath, args: [...] })`，再 `browser.newContext({ viewport: { width: 1280, height: 800 } })`。可注入 `launch` 以便测试。
   - 如果用户已有 `valid` 登录态，用它初始化上下文（可能只需重新登录其中一个站点）
   - 依次处理两个站点：打开站点页面，每秒轮询 `pageLooksLoggedIn`（检查上下文所有页面），**连续 3 次**为真才认为该站点已登录；更新 `sites`。如翼先，DataNexus 后。
   - 两个站点都已登录后，用 `probeSite` 在新页面复查两个站点；复查失败的站点回到等待状态（最多 3 轮，同 `login-export-state.js`）
   - 复查通过：`status='saving'`，`context.storageState({ indexedDB: true })` 得到对象（**不写文件**），`storeCapturedState(db, userId, state, keys)`；`status='succeeded'`；关闭浏览器
   - 任意异常：`status='failed'`，`message` 为中文概括（不含堆栈、不含 cookie），关闭浏览器
2. `cancelSession(sessionId, userId)`：只能取消自己的会话；关闭浏览器，`status='cancelled'`
3. 超时：会话总时长超过 `RUYI_LOGIN_SESSION_TIMEOUT_MS`（默认 15 分钟）→ `expired`，关闭浏览器。用一个 `setInterval` 每 10 秒检查一次，`unref()`。
4. 用户关闭了浏览器窗口（`browser.on('disconnected')` 或所有页面关闭）→ `cancelled`
5. 结束态的会话保留 10 分钟供前端查询，之后从 Map 删除
6. `closeAllSessions()`：服务关闭时调用（`onClose` 钩子）
7. `publicSession(session)`：对外字段 `{ id, status, sites, message, createdAt, expiresAt }`，**不得**包含 browser、context、cookie

### 2. 接口 `server/routes/platform-login.js`（均需登录）
- `POST /api/platform-login` → 开始（或返回已有的）登录会话：`{ ok: true, session }`；超过全局上限 → 409 `登录排队中：当前已有 N 人正在登录，请稍后再试`
- `GET /api/platform-login/:id` → `{ ok: true, session }`；不是自己的会话 → 404
- `DELETE /api/platform-login/:id` → 取消；返回 `{ ok: true }`
- `POST /api/platform-state/clear` → 清除自己的登录态（`clearState`），`{ ok: true }`
- `GET /api/platform-state`（4.1 已有）保留

### 3. 操作记录（`server/audit-actions.js` 或直接在路由中写）
| action | 时机 | result / detail |
|---|---|---|
| `platform.login_start` | 开始会话 | 成功；`detail.sessionId` |
| `platform.login` | 会话结束 | `succeeded` → success；`failed`/`expired` → failure，`detail.status`；`cancelled` 也记为 failure、`detail.status='cancelled'` |
| `platform.logout` | 清除登录态 | 成功 |
会话结束时的记录在会话逻辑里写（不依赖 HTTP 响应），使用开始时的用户和 requestId。`web/src/labels.js` 增加：`platform.login_start: '开始平台登录'`、`platform.login: '平台登录'`、`platform.logout: '清除平台登录'`。

### 4. 登录状态接口改造
- `GET /api/login-status`（认证模式）：不再启动浏览器，改为直接返回数据库状态，保持原响应形状以兼容现有前端：`{ ok: true, sites: { ruyi: valid, datanexus: valid }, loggedIn: valid, state: <getStatusSummary 结果> }`，其中 `valid = summary.status === 'valid'`
- `auth: false` 模式保持原逻辑（旧测试）

### 5. 测试 `test/platform-login.test.js`（数据库测试 `ruyi_test`，加入 `test:all`）
注入假的 `launch`：返回假的 browser/context/page，页面的 URL 和“业务元素是否可见”由测试控制（可直接 stub `pageLooksLoggedIn` 与 `probeSite`，例如通过依赖注入参数 `checks: { pageLooksLoggedIn, probeSite }`）。**不得启动真实浏览器。** 用假时钟或很短的轮询间隔/超时（通过参数注入，例如 `pollMs`、`timeoutMs`）。覆盖：
- 正常流程：starting → waiting → 两站点依次登录 → succeeded；数据库有 `valid` 登录态，解密后等于假 context 的 `storageState()` 返回值；写入 `platform.login_start` 与 `platform.login`（success）
- 业务元素只闪现 1～2 次（不连续 3 次）不算登录
- 复查失败后回到等待，第二轮通过后成功
- 同一用户重复开始返回同一会话；第三个用户超过上限 409
- 取消：浏览器被关闭，状态 cancelled，记录 failure
- 超时：状态 expired，浏览器被关闭
- 用户 B 查询或取消 A 的会话 → 404
- `storageState()` 抛错 → failed，数据库无新登录态，message 不含原始错误
- 接口响应中不含 `cookies`、cookie 值
- `/api/login-status` 认证模式不启动浏览器，返回数据库状态
- `POST /api/platform-state/clear` 后状态为 `expired`
