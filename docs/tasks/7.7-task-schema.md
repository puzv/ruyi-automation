# 业务任务与文件清单入表

本次范围：新增 MySQL 5.7 兼容表结构，不改页面、API、Worker、已有迁移和历史归属；不迁移或读取真实上传文件。后续接入完成前，现有页面状态与执行行为不会改变。

## 数据模型

- `ruyi_tasks`：完整任务编号、名称、所属用户、整体状态、当前步骤、入队顺序、平台轮询时间、执行租约、版本与软删除标记。
- `ruyi_task_files`：任务内文件清单，保存初始文件名、规范化重名键、固定序号、类型、大小、相对路径、平台名称和资源标识、处理阶段及排除标记。文件内容仍在任务独立目录，不存数据库。
- `ruyi_jobs.task_id`：原表继续保存单步骤的每次执行和日志；新增可空外键，明确关联完整任务。同一任务的下载步骤记录可复用现有结果清单与下载接口，不再另存一份结果文件表。
- 文件与执行记录的复合外键保证所属用户与任务一致；不配置级联删除。不同任务允许相同初始文件名，同任务按 NFC UTF-8 字节唯一，不受数据库大小写/重音不敏感排序规则影响。平台名称保持唯一，碰撞时必须重新分配，不能覆盖其他任务。
- 历史 `ruyi_jobs.task_id` 保持 NULL，不以“最近上传”推断并回填。

## 后续业务必须落实的规则（本迁移不自动实现）

1. 创建窗口不落草稿；在有效登录、文件接收及校验成功后才发布任务及清单。未编辑名称时应用写入完整任务编号。临时接收目录不能被 Worker 扫描；数据库事务与文件落盘失败需补偿，不能留下半成品任务。暂不提供后续补传。
2. 整体状态只有 queued / running / waiting_login / succeeded / failed / cancelled / interrupted；不设 draft 或 waiting。等待平台生成结果时仍为 running，使用 next_check_at 调度检查。running 不等于浏览器一直占用，也不等于允许该用户启动下一项任务。
3. 每用户按 queued_at、queue_order 先进先出，整项任务运行期间不启动该用户的下一项任务。平台总并发上限沿用部署配置，不新增可编辑配置表；多 Worker 必须在同一数据库命名锁/事务约束下核对整任务活动数，不能把现有单 Worker 并发上限误作全平台上限。等待平台的 running 任务继续占整任务名额，浏览器执行名额可另行限制。
4. 登录失效时同用户仍可执行的任务统一进入 waiting_login，释放执行名额和租约；不得把失败、取消、中断任务重置为等待登录。登录成功不自动恢复；用户明确恢复时更新 queued_at，清理等待标记并重新入队。
5. 失败、取消、中断不自动重试，也不继续其后续步骤；确认旧进程停止、释放租约后再执行其他任务。服务恢复需校验心跳、租约和平台已提交操作，避免重复创建。
6. 所有自动化读取、原始文件重名检查、待办、平台轮询与结果归属均限定 task_id 对应工作区，不能继续扫描整个用户目录。目录隔离和数据库外键不能替代代码中的用户授权及路径安全校验。
7. 删除文件是设置 excluded_at，保留原名与执行历史，每次进入下一步骤前均过滤。删除与提交平台操作须串行化：推进短事务内锁定任务并核对版本，再认领文件；已认领/发送中的操作不可撤回，应返回明确冲突或等待该操作结束后生效。不能只删表行、目录或页面项。最后一个有效文件被排除时停止任务，未完成任务按取消处理，不报四步成功。
8. 已完成任务删除文件不能篡改过去执行结果。删除任务使用 deleted_at；运行任务先取消并确认退出。审计只追加，原文件清理和结果保留策略另行实施；不能因本地删除而删除平台资源。
9. 任务四步成功且结果清单 ready、文件可读取时展示“下载结果”；通过 task_id 查找所属用户的成功 download 执行记录，复用该 job 的不可变结果清单。没有结果时显示明确原因，不能只凭 succeeded 展示可下载。

- 本地开发库可按迁移顺序执行新增迁移，检查 MySQL 5.7 DDL 与 information_schema。禁止对远程库执行迁移。
- 执行 `npm test`。数据库中的状态枚举和约束是后续实现基础，并不代表队列、文件排除与界面已完成。
