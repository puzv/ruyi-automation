# 7.7 自动推进面板改为进度条动画

## 背景

7.5 的自动推进面板只用一个圆点颜色 + 一行文字表达阶段，用户看不出“走到哪一步、还剩几步”。负责人要求改成进度条动画效果，美术风格由审查方决定（见下文）。

## 范围

只改前端展示：`apps/web/src/views/WorkbenchView.vue`、`apps/web/src/style.css`、`test/frontend-jobs.test.js`。不改服务端、接口、引擎、文案常量 `PHASES`、开关逻辑、15 秒刷新逻辑。

## 进度模型

四个节点、三段轨道：

| 节点 | 0 上传文件 | 1 人群包 | 2 人群洞悉 | 3 结果就绪 |
|---|---|---|---|---|

阶段 → 当前步骤 `step`（正在进行的段落序号 1..3）与 `mode`：

| phase | step | mode | 表现 |
|---|---|---|---|
| `idle` | 0 | `idle` | 空轨道，节点全灰，无动画 |
| `waitingFiles` | 1 | `waiting` | 段 1 流动斜纹（平台处理中，进度未知） |
| `readyCreate` | 1 | `submitting` | 段 1 填满，节点 1 脉冲光环 |
| `waitingAudience` | 2 | `waiting` | 段 1 已填满，段 2 流动斜纹 |
| `readyAnalyse` | 2 | `submitting` | 段 2 填满，节点 2 脉冲光环 |
| `waitingResults` | 3 | `waiting` | 段 3 流动斜纹 |
| `resultsReady` | 3 | `done` | 全部填满为金色，节点 3 金色；进入该状态时一道高光扫过一次（不循环） |
| `stalled` / `error` / `loginRequired` | 由工作区推导 | `blocked` | 当前段变珊瑚色、静止、节点显示感叹号样式 |
| `paused` | 由工作区推导 | `paused` | 当前段灰色静止，已完成段保持淡绿 |

“由工作区推导”：这些阶段服务端返回的 `pending` 为空，用已有的 `statusCounts`，按与引擎 `decide()` 相同的优先级：`createCount > 0` → 1，否则 `analyseCount > 0` → 2，否则 `doneCount > 0` → 3，否则 0。

- 已完成段（序号 < step）实心填充；`submitting` 时当前段也算填满。
- 当前段下方小字显示剩余数：`pending.files` → “剩余 N 个文件”，`pending.audiences` → “剩余 N 个人群包”，`pending.results` → “剩余 N 个洞悉结果”；无数字时不显示。
- 用一个 `computed`（例如 `autoProgress`）集中算出 `{ step, mode, pendingText }`，模板只读它；不要把映射散落在模板里。

## 美术风格

沿用现有工作台的配色与细线风格，不引入新字体或图标库：

- 轨道：高 6px、圆角、底色 `#e6ece9`；已完成 `#73b79a`；提交中节点/光环 `#6b93bd`；完成金 `#ae8839`；阻塞珊瑚 `#c9765f`；暂停灰 `#c8d4cf`。
- 节点：10px 圆点，已完成为实心，当前为白底+彩色描边，未到达为浅灰；节点下方 11px 标签，当前节点标签加粗、颜色加深。
- 流动斜纹：`repeating-linear-gradient` 45° 浅绿/中绿条纹，`background-position` 循环约 1.2s 线性；不要用 JS 计时器驱动动画。
- 脉冲光环：`box-shadow` 或伪元素 `scale` + `opacity` 循环约 1.6s。
- 段间填充宽度切换时 `transition: width .5s ease`，阶段推进时看到条子“长过去”。
- `@media (prefers-reduced-motion: reduce)` 下关闭所有循环动画和高光扫过，只保留静态颜色。
- 窄屏（≤620px）标签可缩小为 10px，不得溢出面板。
- 保留现有面板外框、左侧阶段色条、标题、`role="status"` 文案、开关、`.auto-meta`、`.auto-times`、登录链接；进度条放在标题行与 `.auto-meta` 之间，对齐 `.auto-meta` 的 20px 左缩进。原 `.auto-dot` 可删除或保留，二选一，不要与进度条重复表达。
- 进度条容器 `role="progressbar"`，`aria-valuemin="0"`、`aria-valuemax="3"`、`aria-valuenow` 为已完成步数，`aria-valuetext` 为当前 `autoAdvance.message`。

## 测试要求

在 `test/frontend-jobs.test.js` 中补充（沿用现有 `mount` 方式，不新增依赖）：

- 遍历全部 11 个阶段，断言 `autoProgress` 的 `step` / `mode` 符合上表。
- `stalled` 搭配 `statusCounts` 的 `analyseCount > 0`（`createCount = 0`）时 step 为 2；全为 0 时为 0。
- `waitingFiles` + `pending.files = 3` 时 `pendingText` 含“3”；`pending` 为空时 `pendingText` 为空。
- 现有用例必须保持通过（尤其自动推进相关用例和 `jobTimers()` 过滤）。
- 不得只靠源码字符串断言；可以额外断言 CSS 中存在 `prefers-reduced-motion`，但不能作为唯一测试。

## 审查修复（2026-10-25）

1. 服务端在 `readyCreate` / `readyAnalyse` / `resultsReady` 返回 `pending` 计数为 0，当前会显示“剩余 0 个文件/洞悉结果”。`pendingText` 只在 `mode === 'waiting'` 且计数 > 0 时显示；修正测试中“剩余 0”的断言为空串，并补充 `readyCreate` + `{ files: 0 }`、`resultsReady` + `{ results: 0 }` 为空串的用例。
2. 窄屏（320px 面板）下剩余数文字会折行，改为不折行（`white-space: nowrap`）且仍居中于当前段，不得溢出面板。
3. 阻塞状态 10px 圆点里的 8px “!” 看不清：阻塞时当前节点放大为 14px 实心珊瑚色、白色加粗 “!”，并保持与轨道垂直居中、标签位置不变。
