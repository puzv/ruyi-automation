# 任务 6.0：部署前补充直接注册

## 背景与决定
负责人明确选择在登录页开放直接注册，不使用邀请码或管理员审核。本任务独立于阶段六部署，完成后停下供负责人检查，不继续构建或发布镜像。

## 实现范围
1. 新增公开 `POST /api/auth/register`，复用用户名 3–12 位、密码 8 位以上且最多 72 字节、显示名 1–64 字符校验；仅允许创建普通用户，忽略客户端 role/status/createdBy/mustChangePassword 等权限字段，必须 active、user、无需首次改密。
2. 注册成功返回 201，提示回到登录，沿用已有登录接口；不自动创建会话，重复用户名返回 409，包括并发重复，校验错误 400；不得将密码或哈希放入响应、审计或日志。
3. 鉴权仅放开该 POST 注册路由；其余保护保持。操作记录增加 auth.register 白名单字段，成功关联新建用户，失败不错误关联已存在用户；前端补中文动作标签。
4. 登录页支持登录/注册切换；注册表单包含用户名、显示名、密码、确认密码，提供长度提示、提交防重复、两次密码校验、服务端错误；成功切回登录并保留用户名，清空密码，展示成功提示。不改变登录成功事件与首次改密流程。
5. 新增本地 ruyi_test 注册接口测试和无浏览器前端组件测试，接入 npm run test:all / npm test；README 更新直接注册行为。测试覆盖非法输入、重复/并发、提权字段无效、无session、注册后能登录且普通权限、审计无密码、切换/确认密码/失败重试/成功清理。
