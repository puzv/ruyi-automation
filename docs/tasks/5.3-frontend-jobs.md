# 任务 5.3：前端任务队列与历史任务页面

先阅读 `AGENTS.md`、`docs/REFACTOR_PLAN.md`（“阶段 5 的具体决定”）、5.2 完成的接口（`server/routes.js` 或新的任务路由文件：`POST /api/run/:task`、`GET /api/jobs`、`/api/jobs/active`、`/api/jobs/:id`、`/api/jobs/:id/log`、`/api/jobs/:id/cancel`、`/api/admin/jobs`），以及 `web/src/views/WorkbenchView.vue`、`web/src/App.vue`、`web/src/labels.js`、`web/src/components/LogTable.vue`（表格写法参考）、`web/src/views/AdminLogsView.vue`（管理员页写法参考）。

## 要做的事

### 1. 工作台（`WorkbenchView.vue`）
- 运行任务：`POST /api/run/:task` 返回 `status: 'queued'` 后开始轮询 `GET /api/jobs/:id`（每秒一次）
- 状态提示（替换原来的 `运行中...`）：
  - `queued`：`<任务名>排队中，前面还有 N 个任务`（`position` 为 0 时显示 `<任务名>即将开始`）
  - `running`：`<任务名>运行中...`
  - `succeeded`：保持原有行为（`已完成`，并对上传/创建/洞悉自动“检测当前状态”）
  - `failed`：`<任务名>执行失败：<errorMessage 或 “请查看日志”>`
  - `cancelled`：`<任务名>已取消`；`interrupted`：`<任务名>因服务重启中断，请重新运行`
- 排队中或运行中时，显示“取消任务”按钮 → `window.confirm` 确认后 `POST /api/jobs/:id/cancel`；运行中取消时提示 `正在停止任务…`
- **刷新页面后恢复**：页面加载时调用 `GET /api/jobs/active`，有进行中的任务就继续轮询并显示它的状态和日志
- 日志框（`job-log`）显示接口返回的 `output`（最后 64KB）；任务结束后在日志框下方显示“查看完整日志”链接 → 新标签打开 `/api/jobs/:id/log`
- 有任务排队或运行时，其他任务按钮仍可点击（会继续排队），但同一按钮重复点击要有防抖（请求进行中时禁用）
- `PLATFORM_LOGIN_REQUIRED` 的处理保持不变；`user_limit`（409）显示服务端 message

### 2. 我的任务页（`web/src/views/MyJobsView.vue`，路由 `#/jobs`；侧边栏导航增加“我的任务”）
- 表格列：提交时间、任务（中文名：上传文件 / 创建人群 / 人群洞悉 / 下载结果）、状态（彩色标签：排队中 / 运行中 / 成功 / 失败 / 已取消 / 已中断）、开始时间、耗时（结束时间-开始时间，`X 分 Y 秒`；运行中显示已运行时长）、说明（`errorMessage`）、操作
- 操作：“查看日志”（新标签打开 `/api/jobs/:id/log`）；排队中/运行中显示“取消”
- 分页（同 `LogTable` 的样式），每页 20 条；列表中有排队或运行中的任务时每 3 秒自动刷新
- 任务名与状态的中文映射放在 `labels.js`（`taskLabels`、`jobStatusLabels`），工作台也复用

### 3. 管理员任务页（`web/src/views/AdminJobsView.vue`，路由 `#/admin/jobs`，仅管理员；侧边栏管理员区增加“全部任务”）
- 与“我的任务”相同的表格，额外显示“用户”列
- 筛选：用户名、状态；点“查询”回到第 1 页
- 管理员只查看，不提供取消按钮（取消只能由任务所有者操作，避免误伤；若接口支持管理员取消，也不在本任务中加）
