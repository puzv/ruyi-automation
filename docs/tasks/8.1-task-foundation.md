# 阶段 1：任务基础与文件隔离

接入现有 `ruyi_tasks`、`ruyi_task_files` 和 `ruyi_jobs.task_id`，不修改表结构。新增任务基础 API，保留旧入口与页面，不接入整任务调度。

## 接口

- `POST /api/tasks`：multipart `name`（可选）与 `files`。接收一次初始文件，不提供补传。名称为空时使用完整 UUID。
- `GET /api/tasks?page=1&pageSize=20`：当前用户任务，最新创建优先。
- `GET /api/tasks/:id`：任务详情和明确通过 `task_id` 关联的执行记录。
- `PATCH /api/tasks/:id/name`：JSON `{ "name": "名称" }`，可带 `version` 做乐观锁。
- `GET /api/tasks/:id/files`：原始文件名及状态，不暴露磁盘路径。

仅 Cookie 会话开放，API Token 不新增授权。所有查询限定所属用户，其他用户的 ID 返回 404。

## 文件与发布

每个用户工作区下 `tasks/<任务 UUID>` 保存独立文件，旧脚本只扫描 `raw/idfa/oaid/pn`，不会扫描 `tasks`。上传先流式写入同级 `.incoming-<UUID>` 隔离目录，单文件 1GB、最多 1000 个文件；文件权限 600，目录 700。所有文件校验成功并复查登录态后，目录发布到任务路径，再在单个数据库事务内创建任务和清单。无效类型跳过，零有效文件拒绝；同任务按 NFC 文件名重名拒绝，跨任务可重名。

整次接收总量限制 1GB（包括无效跳过文件），避免通过多个文件耗尽磁盘。物理文件名使用文件 UUID，后续阶段必须以数据库 `file_type`、`original_name` 等清单元数据驱动处理，不能直接套用旧文件名类型推断。

失败不创建数据库可执行半任务。遵守“不删除文件”的项目限制，失败可能保留未发布隔离目录或无数据库记录的任务目录，这些目录不会被旧执行路径扫描，需要另行制定清理方案。

## 阶段边界

任务创建后状态为 `queued`，本阶段**尚未接入整任务执行**，不会创建 `ruyi_jobs`，也不会唤醒旧 Worker；前端入口和队列在后续阶段交付。登录校验复用已有加密登录态读取，不额外打开平台页面验证远端会话。已有历史执行不猜测归属。

## 验证

新增 Node assert 测试覆盖真实 Fastify 路由、Fake DB 事务回滚、Kysely MySQL SQL 编译、所有权、命名、分页、重名、登录检查、隔离和路径安全。`ruyi_test` 缺少新表，禁止修改结构，当前阶段不以 Fake DB 验证代替真实数据库集成测试。执行针对测试及 `npm test`。

## 人工审查步骤

本阶段没有新增页面，后端不是热更新，需由主代理确认当前本地服务后重启后端才会加载接口。在已经登录本地网页的同源浏览器控制台使用下列代码，手动选择自己准备的无敏感内容测试文件（名称例如 `review_oaid.txt`），不要选择仓库真实上传数据：

```js
const picker = document.createElement('input');
picker.type = 'file'; picker.multiple = true;
picker.onchange = async () => {
  const body = new FormData();
  // 不添加 name 即默认完整编号；需要自定义时可 body.append('name', '审查任务')。
  for (const file of picker.files) body.append('files', file);
  const result = await fetch('/api/tasks', { method: 'POST', body }).then(r => r.json());
  console.log(result);
  window.reviewTaskId = result.item?.id;
};
picker.click();
```

1. 未完成平台登录时创建，预期 409、`PLATFORM_LOGIN_REQUIRED`；完成平台登录后创建，预期 201、状态 queued、名称默认完整编号，暂不会执行。
2. 再创建一次选择同名文件，预期成功且新编号不同；同次选择重复 NFC 名称的文件应拒绝整批发布。
3. 查询列表及详情：`await fetch('/api/tasks?page=1&pageSize=20').then(r=>r.json())`、`await fetch('/api/tasks/'+reviewTaskId).then(r=>r.json())`。
4. 查询清单：`await fetch('/api/tasks/'+reviewTaskId+'/files').then(r=>r.json())`；只返回原始名称、类型、大小和阶段等元数据，不含本地路径。
5. 改名：`await fetch('/api/tasks/'+reviewTaskId+'/name',{method:'PATCH',headers:{'Content-Type':'application/json'},body:JSON.stringify({name:'修改后的名称',version:1})}).then(r=>r.json())`；再以旧 version 修改应返回 409。
6. 换另一用户访问相同任务编号，详情、文件清单及改名均应返回 404；日志应出现创建、改名操作及其成功/失败状态。

阶段 1 保持旧操作面板及任务列表原状；新任务不出现在旧的执行记录归并列表中。页面统一展示安排在阶段 5，本阶段通过以上接口审查。
