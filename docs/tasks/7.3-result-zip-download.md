# 7.3 下载结果 ZIP 自动下载与重新下载

## 目标
负责人确认：下载结果任务先保存到 PVC，再在网页打开期间自动发起该任务结果 ZIP 下载；“我的任务”中成功的下载结果任务提供“重新下载”。不代表网页能够确认本地磁盘保存成功。

## 范围与设计
- 6.1 sol 子代理编码，主代理审查及验收。仅本功能的 automation/shared/server/worker/web 与相关测试、说明；不提交、不发布、不迁移数据库。
- 精确记录当前服务端任务 ID 产生的结果文件，在用户工作区保存任务专属清单/不可变结果归档；禁止把 result 全目录打包，禁止仅靠时间或目录差异猜归属。只有真实保存成功的文件进入该任务包。文件保留原始名称，使用实际扩展名。
- 不改现有 result 下载保存行为；清单或归档写入失败须明确报错。归档应允许未来任务处理后仍可重新下载旧任务结果。中断/失败任务不能暴露为成功可下载。
- 用现有依赖或 Node 内建能力生成标准 ZIP，包含中文文件名、CRC 与 ZIP 边界校验；支持流式处理、背压及客户端中断，不将整个文件/ZIP 读入内存。无适合现有依赖可考虑 ZIP STORE；不可自行安装依赖。超过格式限制需明确拒绝，不能损坏压缩包。
- 新增已登录用户自己的任务结果下载接口；仅 download+succeeded 可下载，并校验归属。拒绝路径穿越、任何目录链符号链接/非普通文件，不允许客户端提供路径，使用 Content-Disposition 附件和合适 ZIP 文件名。空结果及旧任务无清单给明确中文提示，不假装可下载。不访问管理员其他用户结果。
- 工作台与我的任务页观察到活动 download 任务转为成功时自动发起一次下载；应用内切页不可重复触发，初次加载历史成功任务不自动下载。网页保持打开且用户未退出时生效，下载失败给提示。优先浏览器直接附件下载而非 fetch 整包 Blob。失败后允许按钮重新下载，不自动重跑平台任务。
- 我的任务成功的 download 行添加“重新下载”（历史无归档可给清晰不可用说明）；其他任务及管理员列表不显示。保留日志、取消、现有轮询。
- 更新文档描述本地下载和旧任务限制。无关目录清理不属于本任务。

## 约束
遵循 AGENTS.md；不读改 .env、*.state.json、state-test.json、ruyi-profile/、upload/ 真实数据。只用临时伪造文件；不能启动 Chromium、连接远程库、安装依赖、提交、创建子代理。已有用户工作区改动完整保留。

## 验证与验收
- 补有意义测试：两个任务/用户隔离、中文及重复命名策略、空结果、历史无清单、失败/取消不可下载、所有路径链符号链接、ZIP 内容可由标准工具解压、文件流/连接取消；前端自动下载去重、切页、历史不触发、重新下载错误。
- 子代理运行专项及 npm test；主代理核对改动、敏感文件 shasum、独立 npm run test:all、npm run build:web，并补 ZIP 解压/浏览器下载冒烟。
- 不操作 K8s，不构建/推送镜像；给出上线后逐步验收清单并停下。

## 负责人验收清单（发布新版镜像后）
1. 保持网页打开，用测试用户完成一次产生多个文件的下载结果任务，确认浏览器只收到一个 ZIP，解压后文件名与内容符合预期。
2. 在“我的任务”找到成功的下载结果任务，点击“重新下载”，确认包内文件与第一次相同。
3. 刷新网页或执行后续任务，再重新下载先前任务，确认不会自动重复下载、不会混入后续任务文件。
4. 关闭网页等待任务结束后再打开“我的任务”，确认能够手动重新下载；用另一用户确认无法访问该任务的下载链接。
5. 在实际 Chrome/Safari 中检查自动下载策略；浏览器拦截自动下载时，用“重新下载”获取文件。旧版本任务无归档时应给出明确提示。
