## 要做的事

### 1. 修正密码规则（`server/auth/password.js`）
bcrypt 只使用密码的前 72 个字节。`validatePasswordStrength` 增加：UTF-8 字节长度超过 72 时返回 `密码不能超过 72 个字节`。补充对应测试。

### 2. 会话工具 `server/auth/session.js`
- 生成令牌：`crypto.randomBytes(32).toString('base64url')`；数据库只存 `sha256(令牌)` 的十六进制（64 位，对应 `ruyi_user_sessions.id`）
- Cookie 名 `ruyi_session`；`httpOnly`、`sameSite: 'lax'`、`path: '/'`、`maxAge` 7 天；`secure` 由环境变量 `RUYI_COOKIE_SECURE=1` 打开（开发环境是 http）
- 规则：会话最长 7 天（`expires_at = 创建时间 + 7 天`）；闲置超过 8 小时失效
- 修改 2.1 的 `server/repos/sessions.js`（允许）：
  - `findActiveSession(db, tokenHash, { idleMinutes })`：增加条件 `last_seen_at > DATE_SUB(NOW(), INTERVAL idleMinutes MINUTE)`
  - `touchSession`：只在 `last_seen_at < DATE_SUB(NOW(), INTERVAL 1 MINUTE)` 时更新，避免前端每秒轮询都写库
  - 更新 `test/db-repos.test.js` 中受影响的测试

### 3. 应用装配（`server/app.js`、`server/index.js`）
- `buildApp(options)` 新增：
  - `options.db`：Kysely 实例，用 `app.decorate('db', db)` 挂载
  - `options.auth`：默认 `true`。为 `true` 时**必须**提供 `db`，否则 `buildApp` 直接抛错（防止生产环境在未配置数据库时以无鉴权方式启动）。`auth: false` 只供不涉及鉴权的旧测试使用
- 注册 `@fastify/cookie`
- `server/index.js`：用 `createDb()` 创建连接并传入；缺少数据库配置时打印中文错误并以非 0 退出；`app.close()` 时一并 `db.destroy()`（用 `onClose` 钩子）
- 更新 `test/server-app.test.js`、`test/server-routes.test.js`：传 `auth: false`，原有断言不变

### 4. 鉴权钩子（`server/auth/guard.js`，在 `buildApp` 中以 `onRequest` 钩子注册，仅作用于 `/api/` 路径）
- 公开接口：`GET /api/health`、`POST /api/auth/login`
- 其余 `/api/*` 需要有效会话，否则 401 `{ ok: false, code: 'UNAUTHENTICATED', message: '请先登录' }`
- 有效会话时把用户挂到 `request.user`（`{ id, username, displayName, role, mustChangePassword }`），把令牌哈希挂到 `request.sessionTokenHash`，并调用 `touchSession`
- `mustChangePassword` 为真时，只允许 `GET /api/auth/me`、`POST /api/auth/change-password`、`POST /api/auth/logout`，其他返回 403 `{ ok: false, code: 'PASSWORD_CHANGE_REQUIRED', message: '请先修改密码' }`
- `/api/admin/*` 要求 `role === 'admin'`，否则 403 `{ ok: false, code: 'FORBIDDEN', message: '没有权限' }`
- 页面和静态文件不受影响（前端在 2.4 中处理登录跳转）

### 5. 认证接口（`server/routes/auth.js`）
- `POST /api/auth/login` `{ username, password }`
  - 参数缺失 → 400
  - 用户不存在 → 也执行一次 bcrypt 比较（用固定的假哈希）以拉平耗时，返回 401 `用户名或密码错误`
  - 账号当前处于锁定期（用数据库时间判断，例如 `locked_until > NOW()`）→ 429，提示 `登录失败次数过多，请 N 分钟后再试`（N 向上取整），**不校验密码、不累加失败次数**
  - 密码错误 → `recordLoginFailure(maxFailures 5, lockMinutes 15)`，返回 401 `用户名或密码错误`
  - 密码正确但账号已停用 → 403 `账号已停用，请联系管理员`
  - 成功 → `recordLoginSuccess`，创建会话，设置 Cookie，返回 `{ ok: true, user }`
  - IP 取 `request.ip`，User-Agent 截断到 255 字符
- `POST /api/auth/logout`：撤销当前会话，清除 Cookie，返回 `{ ok: true }`
- `GET /api/auth/me`：返回 `{ ok: true, user }`
- `POST /api/auth/change-password` `{ currentPassword, newPassword }`：校验当前密码（错误返回 400 `当前密码不正确`，**不计入**登录失败次数）、校验新密码强度、新旧密码不能相同；成功后更新密码、`must_change_password = 0`，撤销该用户的**其他**会话，返回 `{ ok: true }`

### 6. 管理员接口（`server/routes/admin-users.js`）
- `GET /api/admin/users` → `{ ok: true, users }`（字段用驼峰，不含密码哈希）
- `POST /api/admin/users` `{ username, displayName, password, role }`：校验用户名、密码强度；`role` 只能是 `user` / `admin`；新用户 `must_change_password = 1`，`created_by` = 当前管理员；用户名重复返回 409 `用户名已存在`
- `POST /api/admin/users/:id/disable`：不能停用自己（400）；停用后撤销其全部会话
- `POST /api/admin/users/:id/enable`
- `POST /api/admin/users/:id/reset-password` `{ password }`：更新密码，`must_change_password = 1`，撤销其全部会话
- 用户不存在返回 404

### 7. 测试 `test/server-auth.test.js`（数据库测试，连 `ruyi_test`）
- 与 `test/db-repos.test.js` 相同的保护：`RUYI_DB_NAME` 不是 `ruyi_test` 时直接失败；开始和结束时用 `DELETE` 清空四张 `ruyi_` 表的数据
- 防护照搬 `test/server-routes.test.js` 开头：测试中不得启动浏览器或子进程
- 覆盖：
  - 未登录访问 `/api/status` → 401；`/api/health` → 200
  - 登录成功返回 Set-Cookie（httpOnly、SameSite=Lax），用该 Cookie 访问 `/api/status` → 200，`/api/auth/me` 返回用户
  - 用户名不存在与密码错误返回相同的状态码和提示
  - 连续 5 次错误后第 6 次即使密码正确也返回 429；把数据库中 `locked_until` 改到过去后可以登录
  - 停用用户：密码正确返回 403；已有会话立即失效（401）
  - `must_change_password` 用户只能访问 me / change-password / logout，其他 403；修改密码后可正常访问，且其他会话失效、当前会话保留
  - 普通用户访问 `/api/admin/users` → 403；管理员可以创建、停用、启用、重置密码；不能停用自己；重名 409
  - 退出后 Cookie 失效
  - 伪造的 Cookie、已过期会话（把 `expires_at` 改到过去）、闲置超时会话（把 `last_seen_at` 改到 9 小时前）都返回 401
  - `buildApp({ auth: true })` 不传 `db` 时抛错
