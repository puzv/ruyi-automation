# 平台等待任务释放执行名额

## 目标和边界

平台返回尚未就绪时，整任务保留“运行中”，但释放全局自动化执行名额；两分钟后重新参与调度。同一用户仍仅推进一个整任务，不能因为前一个任务正在等待平台而执行该用户的下一个任务。

不修改表结构、等待间隔或用户显式恢复登录队列的规则，不主动恢复已有中断任务。

## 实现说明

- 使用已有 `next_check_at` 保存下一次检查时间。流程结束且没有活跃子流程后，在数据库认领锁内清除整任务的 `claim_token`、`worker_id`、`heartbeat_at`。
- 全局并发上限统计持有租约的运行中整任务和独立运行中的旧流程任务，不统计等待平台且已释放租约的整任务。
- Worker 不再保留等待中的执行循环；检查到期后，按到期时间与排队任务的入队时间排序，获取新租约继续当前步骤。
- 同用户串行仍按整任务“运行中”约束，因此等待中的任务不会放行同用户后续任务。其他用户可使用已释放的名额。
- 旧租约不能新增子流程或推进文件状态；创建子流程前同时复查整任务租约、用户、步骤和停止状态。
- 已释放租约的等待任务不会被心跳超时回收为中断，服务重启后仍可按到期时间重新调度。
- 停止等待任务时立即设为“已中断”，不依赖已经退出的执行循环；停止和释放租约之间的竞争用原子更新处理。
