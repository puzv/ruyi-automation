# 任务 2.4：前端登录、修改密码、操作记录与用户管理页面

先阅读 `AGENTS.md`、`docs/REFACTOR_PLAN.md`，以及 2.2、2.3 完成的接口：`server/routes/auth.js`、`server/routes/admin-users.js`、`server/routes/logs.js`、`server/auth/guard.js`（401/403 的 `code` 字段）。前端代码在 `web/src/`（`App.vue` 约 370 行、`style.css`、`main.js`）。

## 约束
- **不安装任何依赖**（不引入 vue-router、UI 组件库等）。用 Vue 3 组合式 API + 已有的 `lucide-vue-next` 图标。
- **现有工作台功能和外观保持不变**：操作卡片、状态面板、运行模式、释放 Profile、平台登录按钮等逻辑不改，只做必要的结构调整。
- 不修改 `server/`。不修改 `web/vite.config.js`、`web/package.json`。
- 新样式沿用 `style.css` 现有的配色与风格（深绿侧边栏 `#15211f`、浅色背景 `#f5f7f4`、卡片白底细边框、圆角 6–10px、字号 11–14px），写在 `style.css` 末尾。

## 要做的事

### 1. 拆分组件（`web/src/`）
- `App.vue`：只负责“当前用户”状态和视图切换
- `views/LoginView.vue`：登录页
- `views/ChangePasswordView.vue`：修改密码（强制修改与主动修改共用）
- `views/WorkbenchView.vue`：把现有 `App.vue` 的工作台内容**原样**搬进来（脚本与模板），只把侧边栏导航改为下面的新导航
- `views/MyLogsView.vue`：我的操作记录
- `views/AdminUsersView.vue`：用户管理（管理员）
- `views/AdminLogsView.vue`：全部操作记录（管理员）
- `api.js`：封装 `fetch`：统一 `credentials: 'same-origin'`；JSON 请求自动加 `content-type`；收到 401 且 `code === 'UNAUTHENTICATED'` 时触发全局“已退出登录”事件（App 切回登录页）；收到 403 且 `code === 'PASSWORD_CHANGE_REQUIRED'` 时触发“需要修改密码”事件。工作台原有的 `fetch('/api/...')` 调用改为使用这个封装（只改调用方式，不改逻辑）

### 2. 视图切换（不用 vue-router）
- 用 `location.hash` 表示当前页面：`#/`（工作台）、`#/logs`（我的记录）、`#/admin/users`、`#/admin/logs`、`#/password`；监听 `hashchange`
- 启动时调用 `GET /api/auth/me`：
  - 401 → 显示登录页
  - 用户 `mustChangePassword` 为真 → 只显示修改密码页（不能离开，只能修改或退出）
  - 普通用户访问管理员页面 → 回到工作台
- 登录成功后进入工作台（或强制修改密码页）

### 3. 侧边栏
- 保留现有品牌区和“平台已登录/需要登录”按钮
- 导航项：操作面板（`#/`）、我的操作记录（`#/logs`）；管理员额外显示：用户管理、全部操作记录
- 原来指向 `#operations` / `#status` 的两个锚点链接：保留“操作面板”，删除“运行状态”（它只是页面内锚点，工作台内仍可滚动看到）
- 侧边栏底部（`sidebar-footer`）显示当前用户显示名和用户名，以及“修改密码”“退出登录”两个按钮；退出调用 `POST /api/auth/logout` 后回到登录页

### 4. 登录页
- 居中卡片：品牌标识、用户名、密码、登录按钮；回车提交；提交中禁用按钮
- 显示服务端返回的中文错误（如“用户名或密码错误”“登录失败次数过多，请 N 分钟后再试”）
- 用户名输入框 `autocomplete="username"`，密码 `autocomplete="current-password"`

### 5. 修改密码页
- 当前密码、新密码、确认新密码；前端先校验两次一致、至少 8 位，再提交 `POST /api/auth/change-password`
- 强制修改时页面顶部说明“首次登录或密码被重置，请先修改密码”，只提供“退出登录”作为其他操作
- 成功后刷新 `GET /api/auth/me` 并进入工作台

### 6. 我的操作记录
- 表格列：时间、操作、对象、结果、说明、IP
- “操作”列把 action 编码显示为中文：`auth.login` 登录、`auth.logout` 退出、`auth.password_change` 修改密码、`admin.user_create` 创建用户、`admin.user_disable` 停用用户、`admin.user_enable` 启用用户、`admin.password_reset` 重置密码、`admin.logs_view` 查看操作记录、`file.import` 导入文件、`job.start` 启动任务、`job.finish` 任务结束、`platform.login_open` 打开平台登录、`profile.release` 释放 Profile、`runtime.mode_change` 切换运行模式；未知编码原样显示。把这个映射放在 `web/src/labels.js` 中，供两个记录页共用
- 任务类型 `detail.task` 显示为中文：upload 上传文件、create 创建人群、analyse 人群洞悉、download 下载结果
- “说明”列：失败时显示 `errorMessage`；`file.import` 显示“导入 N 个，跳过 M 个”；`job.finish` 显示任务名、耗时（秒）和退出码；登录失败显示原因（`unknown_user` 用户名不存在、`wrong_password` 密码错误、`locked` 账号锁定、`disabled` 账号停用、`invalid_request` 请求无效）
- 结果用颜色标签（成功绿、失败红）
- 时间显示为 `YYYY-MM-DD HH:mm:ss`（北京时间）。注意：接口返回的 `createdAt` 由 mysql2 按 `+08:00` 转成了 ISO 字符串，前端用 `toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai', hour12: false })` 之类的方式格式化
- 按操作类型筛选（下拉框）；分页（上一页/下一页、第 X / Y 页、共 N 条），每页 20 条

### 7. 用户管理（管理员）
- 用户列表：用户名、显示名、角色、状态、上次登录时间与 IP、是否需改密码
- “新建用户”表单：用户名、显示名、初始密码、角色；提交后提示“请把初始密码告知用户，首次登录需修改”
- 每行操作：停用 / 启用（不能停用自己：自己的行不显示停用按钮）、重置密码（弹出输入框输入新的临时密码）
- 停用和重置前用 `window.confirm` 二次确认
- 操作后刷新列表，显示服务端返回的错误信息

### 8. 全部操作记录（管理员）
- 与“我的操作记录”共用表格组件（建议 `components/LogTable.vue`），额外显示“用户”列和 User-Agent（可放在鼠标悬停提示里）
- 筛选：用户名、操作类型、结果（全部/成功/失败）、开始日期、结束日期（`<input type="date">`）；点“查询”回到第 1 页

### 9. 构建与检查
- `npm --prefix web run build` 必须成功，且没有新的警告
- `npm run test:all` 仍然通过（不需要新增后端测试）
