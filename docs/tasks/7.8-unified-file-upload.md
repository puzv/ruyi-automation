# 7.8 合并文件选择与平台上传

## 目标

把操作面板中分离的“选择文件夹”和“上传文件”整合为一个“上传文件”入口。用户可从统一入口选择多个文件或整个文件夹；符合条件的文件导入工作区后，自动提交现有平台上传任务。

## 范围

- 仅调整操作面板上传入口及其前端测试，不改 API、Worker、自动化上传规则或数据目录结构。
- 入口提供“选择文件（可多选）”和“选择文件夹”两种方式；文件选择支持多选，文件夹选择使用现有 `webkitdirectory` 能力。
- 两种选择方式共用现有文件名/扩展名筛选、`/api/import-folder` 导入接口及提示。Safari 等不支持文件夹选择的浏览器仍可多选文件。
- 导入成功且至少新增一个有效文件后，自动调用现有 `/api/run/upload`。导入失败、取消选择、未找到有效文件或导入数量为零时不得提交上传任务。
- 上传任务仍按现有逻辑处理工作区中的待上传文件；既有任务状态、排队提示、取消、轮询与自动推进行为保持有效。
- 界面清楚提示文件条件：文件名包含 `idfa`、`oaid` 或 `pn`，扩展名为 `.txt` 或 `.csv`。

## 验证

- 前端测试覆盖从文件和文件夹入口选择、导入成功后只提交一次上传任务，以及取消/无有效文件/导入失败时不提交。
- 运行相关前端测试、`npm test`、`npm run build:web`、`git diff --check`。
- 不启动 Chromium，不读取 `.env`、状态文件、Profile 或 `upload/` 数据；不提交或推送。

## 限制

- 文件夹选择依赖浏览器 `webkitdirectory` 支持；不支持时保留多文件选择能力。
- 当前平台上传任务处理工作区里全部待上传文件，因此此前导入但尚未上传的文件也会随本次任务提交。
