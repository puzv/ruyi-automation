# 任务 1.5：精简服务日志

先阅读 `AGENTS.md`。只修改 `server/app.js`（以及需要时新增测试），不要改其他业务代码。

## 问题
负责人验收时发现：`npm start` 后终端被 Fastify 默认的 JSON 请求日志刷屏（前端每秒轮询一次 `GET /api/jobs/:id`，每次产生两行 JSON），真正有用的输出（例如“人群列表检查页面已关闭。”）被淹没。

## 要求
1. 关闭 Fastify 默认的逐请求日志（`disableRequestLogging: true`）。
2. 只为以下请求打印**一行**易读日志（用 `onResponse` 钩子，通过 `request.log` 或 `app.log` 输出）：
   - 所有非 GET 的 `/api/` 请求（例如 `POST /api/run/create`、`POST /api/import-folder`）
   - 任何状态码 ≥ 400 的 `/api/` 请求
   - 静态文件、页面、以及 2xx/3xx 的 `GET /api/` 请求不打印
   - 格式示例：`POST /api/run/create 200 17ms`
3. 日志输出改为易读格式，而不是每行一个 JSON：
   - 不引入新依赖（不要安装 pino-pretty）。
   - `buildApp` 的 `logger` 选项保持可传入（测试中传 `false`）；默认值改为一个只输出 `level` ≥ info 的简单配置，并且把 Fastify 启动时的 “Server listening at …” 保留下来（这一行很有用）。
   - 可行做法：默认 `logger` 使用 pino 的 `transport` 以外的方式，例如传入一个自定义的 `stream`（`{ write(line) { 解析 JSON，输出 "时间 级别 msg" 到 stdout } }`）。时间用本地时间 `HH:mm:ss`。
4. 保留 Fastify 的错误日志（500 错误仍要打印错误信息和堆栈）。

## 测试
新增或扩展测试：构造 `buildApp({ logger: { level: 'info', stream: 收集数组 } , webDist })`（或你设计的等价可注入方式），验证：
- `GET /api/status`（200）不产生请求日志
- `POST /api/run/unknown`（404）产生一行包含 `POST /api/run/unknown 404` 的日志
- `GET /`（页面）不产生请求日志
测试中照旧不得启动浏览器或子进程（参考 `test/server-routes.test.js` 开头的防护写法）。

## 完成标准
- `npm test` 全部通过。
- 用中文说明默认日志的实际输出样例。
