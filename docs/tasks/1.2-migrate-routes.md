可以按需调整拆分方式，但不要合并成一个巨型文件，也不要改变函数内部逻辑。

## 必须注意的差异（Express → Fastify）
1. **空 JSON 请求体**：前端 `POST /api/profile-release` 带 `content-type: application/json` 但没有请求体，Fastify 默认会返回 400 `FST_ERR_CTP_EMPTY_JSON_BODY`。必须让空 JSON 请求体被当作 `{}` 处理（例如为 `application/json` 自定义 content-type parser，空字符串返回 `{}`，否则 `JSON.parse`，非法 JSON 返回 400）。`POST /api/login-open` 和 `POST /api/run/:task` 不带 content-type，也必须正常工作。
2. **JSON 大小限制**：原来是 `express.json({ limit: '2mb' })`，保持 2MB。
3. **multipart**：用已安装的 `@fastify/multipart` 替换 multer，行为与原来一致：读入内存后按原逻辑写入 `raw/`（文件名解码、过滤、路径穿越检查、已存在不覆盖），返回 `{ ok, count, skipped }`；出错返回 400 和 `{ ok: false, message }`。不要限制单文件大小低于原来的行为（multer 原来没有设限制；把 `fileSize` 设为足够大，例如 1GB，并在代码注释说明后续阶段会改为流式写盘）。注意 multer 与 busboy 对文件名编码的处理可能不同，原来的 `decodeUploadedFileName` 必须照常调用。
4. **错误响应格式**：原接口出错时返回 `{ ok: false, message }`。Fastify 默认错误格式不同；为 `/api/` 设置 `setErrorHandler`，未处理的异常统一返回 `{ ok: false, message }`，状态码沿用错误自带的 `statusCode`，否则 500。
5. **404**：保留 1.1 已有的 `/api/*` 未注册 404 处理，确保新注册的接口不会被它吞掉（注意注册顺序或改用 `setNotFoundHandler` 区分）。
6. **`require` 路径**：原文件用 `createRequire` 加载 `../lib/browser.js`、`../lib/preflight.js`、`../config.js`；`server/` 下直接用相对路径 `require`。`projectRoot` 指向仓库根目录，`uploadRoot` 仍来自 `process.env.RUYI_UPLOAD_DIR || <根目录>/upload`（与 `config.js` 一致，可直接用 `config.uploadRoot`）。
7. **子进程**：`/api/run/:task` 启动的脚本路径、`cwd`、`env`（含 `RUYI_HEADLESS`）、`detached: true` 保持不变。
8. **服务关闭**：在 Fastify 的 `onClose` 钩子中关闭仍在跟踪的浏览器上下文（`activeContexts`），不要杀死正在运行的任务子进程（保持原行为：原来 Vite 退出时也不会主动杀子进程）。

## 测试（新增 `test/server-routes.test.js`，加入 `npm test`）
使用 `app.inject()`，并通过环境变量 `RUYI_UPLOAD_DIR` 指向临时目录（测试开始前设置，注意 `config.js` 在首次 `require` 时读取环境变量，测试文件要在 require 服务代码前设置）。**测试中不得启动浏览器、不得访问外网、不得启动真实任务脚本。**
至少覆盖：
- `GET /api/status`：临时目录中放入 `raw/a_idfa.txt`、`oaid/b_oaid.txt`、`oaid/done/c_oaid.txt`、`createGroupToDoList.json`（`["x_pn.txt"]`）、`done.json`（`["y"]`）后，返回 `ok: true`、`rawCount: 2`、`createCount: 1`、`doneCount: 1`、`workspaceStatus: '等待创建人群包'`
- `GET /api/runtime-mode` 返回布尔 `headless`；`POST /api/runtime-mode` 传 `{ headless: false }` 后再 GET 为 `false`；传 `{ headless: 'x' }` 返回 400 和原中文提示
- `POST /api/profile-release` 在 `content-type: application/json` 且请求体为空时**不返回 400**（可在测试中先把共享状态的 `profileReleaseRunning` 设为 true，期望得到原逻辑的 409 和中文提示，以避免真正执行释放）
- `POST /api/import-folder`：上传两个文件 `测试_idfa.txt`（内容任意）和 `notes.md`，返回 `{ ok: true, count: 1, skipped: 1 }`，且 `raw/测试_idfa.txt` 存在、内容一致；再次上传同名文件返回 400 且 message 含“文件已存在”
- `POST /api/run/unknown` 返回 404 和 `未知操作`
- `GET /api/jobs/不存在` 返回 404 和 `任务不存在`
- `POST /api/run/upload` 在已有运行中任务时返回 409（在共享状态的 `jobs` 中放一个 `{ running: true }` 的假任务，不要真正启动脚本）
- 非法 JSON 请求体（如 `POST /api/runtime-mode` 发送 `{bad`）返回 400 且 `ok === false`
- 测试结束清理临时目录、关闭 app

`login-status`、`login-open`、`platform-status` 会启动浏览器，不写调用测试；但要保证它们已注册（例如在 `profileProbeRunning = true` 时调用 `GET /api/login-status`、`GET /api/platform-status`，期望得到原代码中的 409 和中文提示）。
