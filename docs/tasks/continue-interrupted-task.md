# 继续中断任务

“我的任务”仅为已中断任务提供“继续任务”按钮。确认平台登录有效后，用户明确确认，将单个任务从未完成步骤重新加入队尾；不恢复其他任务、不重新上传已完成文件。

接口：`POST /api/tasks/:id/continue`，正文 `{ version: 正整数 }`。归属与软删除校验、同认领命名锁、行锁及版本比较确保重复请求只成功一次。存在活跃子流程时拒绝恢复。保留任务编号、文件状态、工作目录及全部流程历史，清除旧租约、取消标记与结束信息。

若当前步骤最近一条流程记录已成功（服务可能在推进下一步前停止），从下一步继续；下载已成功则直接恢复整任务为成功。其他情况保留当前步骤并沿用执行清单继续。操作记录追加 `task.continue`，管理员全部任务页面保持只读。

验证：任务安全 SQL 编译测试、真实 buildApp 路由/登录校验、前端 VM、Worker 从 analyse 继续至 download、浏览器 mock 点击及排队状态检查。未访问外部平台、未修改数据库结构。

## 主动停止后继续

运行中任务的“停止任务”调用独立 `POST /api/tasks/:id/stop`，正文 `{ version: 正整数 }`。仅所属用户的未删除运行中任务可以按版本请求停止；停止期间保留运行状态，待子流程实际退出后转为“已中断”，然后显示“继续任务”。等待外部平台处理时，Worker 的停止检查会唤醒重试等待，无需等下一轮平台检查。

终态持久化时原子检查停止标志，已接受的停止请求优先于随后完成或失败的结果；清理停止标志、重试时间及旧租约，避免永久显示“正在停止”。服务异常回收同样清理这些字段。停止不会重置已完成步骤或文件清单，旧 Worker 仍需匹配租约才能写入。实际删除任务及删除最后一个文件的取消语义保持独立。操作记录追加 `task.stop`（停止任务），不再把停止入口记录成删除任务。

回归覆盖执行中停止且等待退出、平台等待中及时停止、停止与成功/抛错/登录失效竞态、终态清理、版本与归属校验、独立停止接口及前端请求。历史“已取消”数据不自动映射为“已中断”。
