# 7.6 自动推进状态与平台检查安全修复

## 目标

修复对当前 7.5 自动推进改动的代码审查发现：不同批次相同待办数量会被旧提交记录误判停滞；平台探测进行中关闭开关仍可能提交任务；平台列表接口异常结构会被当作成功空列表。并收紧近期活动限制，避免无关任务活动意外接管旧待办。

## 范围

- 修复 `apps/server/src/modules/auto-advance/engine.js` 的待办签名：同一数量但不同文件/平台名称的工作流必须有不同签名；批次/待办改变后清除旧 `lastAttempt`，开启/关闭开关不应让旧 attempt 污染后续新工作流。
- 开关在探测前、探测后和自动入队前均须遵守最新持久化值。探测期间被关闭时不得自动提交；并发切换应以数据库里最近一次设置为准。保留提交操作与自动日志的正确顺序，不能出现任务已排入但接口报告失败。
- `apps/server/src/modules/files/platform.js` 中人群列表接口必须校验 HTTP 成功、JSON/API 成功字段及 `data.listing.items` 结构。网络/接口错误或结构异常必须抛出可重试错误；只有有效空列表才表示目标暂未出现。
- 负责人确认：近期活动按阶段关联任务判断，不能由任意不同类型的任务活动解锁旧待办。明确 create/analyse/download 各阶段认可的近期任务类型，并为 SQL/repository 增加测试。
- 保留已定的保守行为：目标未出现在有效列表中算未就绪；洞悉记录缺失算未就绪；禁用期间不推进；不自动下载。

## 补充范围（2026-10-25 审查）

- `wake()` 只安排检查，不清除同一工作流的自动提交记录；真实任务结束通知和前端重复 check 都不能绕过防重复提交。开关恢复也不能隐式重复提交已经失败且未推进清单的任务。
- 同用户开关写入与自动入队必须协调，明确以实际入队为界；关闭请求返回后不能因之前等待中的提交新增任务。旧检查发现设置版本改变时丢弃结果，不能覆盖最新开启状态或将它永久暂停。
- 人群与洞悉只接受明确成功状态，未知、失败、缺失、小写处理中均不能误判就绪；统一大小写处理，修正固化错误预期的测试。
- 人群列表不能因连续三页无匹配就结束，按有效分页结束条件遍历并在全部目标确认后提前退出；达到安全页数上限仍未找齐时保持未就绪。
- 洞悉列表同样校验 HTTP、业务响应和 items 数组结构，不能把接口失败伪装成正常等待。
- 保留单实例部署假设，本次不引入多实例协调或多用户并发探测；并发优化另行安排。
- 行为回归覆盖任务完成 wake 后待办不变、探测期间关闭再开启、提交等待期间关闭、同用户并发开关，以及目标在第四页的列表。
- 全量验收发现 `test/platform-state.test.js` 的 API 启动桩尚未同步引擎先创建后注入 app 的逻辑：同步桩与启动顺序断言，并验证引擎实例和 Worker 结束回调关联；不更改实际入口启动行为。

## 测试要求

- `test/auto-advance.test.js`：复现先完成批次 A、待办归零、再出现相同数量批次 B；检查 B 不被旧 `lastAttempt` 误判 stalled 且会按需推进。
- 用暂停中的平台探测模拟检查期间关闭开关，断言不会 enqueue；检查过程再开启时按最新值恢复；覆盖检查开始前切换。
- `test/platform-inspect.test.js`：有效空列表、HTTP/API 失败、缺失/错误类型 listing.items 均有明确不同结果；不启动浏览器。
- `test/auto-advance-repo.test.js`：阶段对应任务类型过滤及旧的无关任务不满足近期活动要求。
- 不得只靠源码字符串断言；使用 Node `assert` 和现有依赖注入/本地 ruyi_test 测试模式。

## 约束

- 不读取、修改或打印 `.env`、`state-test.json`、`*.state.json`、`ruyi-profile/`、`upload/` 实际数据。
- 不连接远程数据库，不执行迁移；只修改新增逻辑与测试，不改已有 migration，不更改其它用户预存改动。
- 不改 UI 文案/样式、部署、依赖或已提交的 ZIP 结果功能；不提交、不构建/推送镜像。
- 编码代理使用 `gpt-6.1-sol`，不启动 Chromium。
