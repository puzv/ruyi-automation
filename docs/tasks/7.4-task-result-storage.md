# 7.4 下载结果直接按任务保存

## 目标
负责人确认取消新网页下载任务的公共 result 副本，直接保存到用户 job-results/<下载任务ID>/files/<原始文件名>，每个结果只持久保存一份。保留 ZIP 自动下载与重新下载。

## 范围
- 6.1 sol 子代理实施，主代理审查。只修改 shared/runtime/job-results.js、automation/lib/file-manifest.js、相关测试与 README；必要时调整 Worker 测试 fixture。
- 新建任务清单使用新版本或明确格式标记，文件存 files/ 下，保留原始名称和实际扩展名；同任务同名不覆盖，不同任务同名允许。保存后立即登记精确任务清单，不再写公共 result/，不再复制第二份。Playwright 临时下载源可复制一次到最终路径，不要求跨文件系统 rename。
- 负责人进一步确认旧归档尚未上线使用，无需保留 version 1/N.bin 重新下载兼容；仅接受新的任务文件存储格式，旧格式明确拒绝。禁止迁移、读取、清理真实用户数据。新格式校验文件名、路径、目录链、符号链接、普通文件及大小，安全性不降低。
- 清单记录失败不能留下无法重试的最终文件；只回滚本次创建的文件，不删除已有文件。下载失败不推进自动化清单。
- 没有 RUYI_RESULT_JOB_ID 的旧直接脚本可保持兼容，不在本任务删除单机代码。
- 不改数据库、前端行为、部署配置、依赖；不提交，不构建/推送镜像，不操作线上。

## 约束
遵守 AGENTS.md，不读取 .env、state-test.json、*.state.json、ruyi-profile/、upload/ 实际数据。只能用临时伪造数据。子代理不可启动 Chromium、安装依赖、连接远程数据库、提交或创建子代理。保留工作区既有改动。

## 验收
- 补测新任务只有 files/ 一份文件且无 result/、相同用户不同任务同名隔离、同任务拒绝覆盖、旧格式拒绝、中文名与扩展名、路径/符号链接/失败回滚；保留所有 ZIP/接口回归。
- 子代理运行专项和 npm test，报告实际文件与测试。主代理独立审查、标准 ZIP 解压、npm run test:all、npm run build:web、git diff --check，shasum 确认敏感文件未变。
- 完成后报告本地实现和待部署状态，提供验收步骤。

## 用户验收步骤（更新镜像后）
1. 发起“下载结果”，保持任务页面打开，成功后确认浏览器发起 ZIP 下载且解压文件名、内容正确。
2. 在成功任务操作中点击“重新下载”，确认得到相同任务结果。
3. 另一个下载任务生成同名文件，确认两个任务的 ZIP 各自只包含本次结果。
4. 检查 PVC 中新结果只在 `users/<用户名>/job-results/<下载任务ID>/files/` 保存，清单在同任务目录，不新增公共 `result/` 副本；现有旧数据不变。
