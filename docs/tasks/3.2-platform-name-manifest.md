# 任务 3.2：平台名称与初始文件名映射

先阅读 `AGENTS.md`、`docs/HANDOFF.md`、`docs/REFACTOR_PLAN.md`，以及 `uploadAll.js`、`upload.js`、`createGroup.js`、`analyse.js`、`download.js`、`createAllGroup.js`、`analyseAll.js`、`downloadAll.js`、`server/platform.js` 和相关测试。

## 目标

不新增文件清单数据库表。平台名称不包含初始文件名，使用用户名、文件类型、任务 ID 短串和序号构造唯一名称；用户目录中的 JSON 清单保存平台名称与初始文件名的对应关系，下载完成后恢复初始文件名。

## 命名规则

- 逻辑格式为 `<username>_<type>_<job-key>_<sequence>`，其中 `type` 只能是 `idfa`、`oaid`、`pn`。
- `job-key` 从服务端 `RUYI_JOB_ID` 稳定生成，完整任务 ID 也必须写入映射记录；平台显示名按现有规则限制为最多 30 个 Unicode 字符。
- 同一上传任务内同一类型的多个文件必须通过序号区分；序号从 1 开始且在任务内稳定。
- 不能把平台名称截断成互相重复的值；无法在 30 字符内保持唯一时，任务必须在上传前报中文错误并停止。

## 集成约定（负责人确认后的补充）

- `uploadAll.js` 是上传任务入口，用户名和完整任务 ID 由 3.1 传入；同一次上传的全部 raw、idfa、oaid、pn 待处理文件共享任务 ID，但文件序号不同。历史 done 文件与其他已完成任务不计入本次重名检查。
- 新导入文件位于 `raw/<导入唯一标识>/<文件序号>/<原文件名>`；同时兼容旧 raw 平铺文件。递归枚举不跟随符号链接，任务级重复检查在任何改名、移动、浏览器操作前完成。
- 推荐新增 `lib/file-manifest.js`，映射文件命名为 `file-manifest.json`；由 3.2 唯一负责此模块。先完整预检，再持久化映射和准备文件，重试时沿用已有平台名称，不能因为新的服务端任务 ID 再次改名或重复分配。
- 类型必须依据记录中的 `type` 或原始文件类型获取，不能用平台名中的任意 `pn/idfa/oaid` 子串判断；用户名本身可能含这些字母。
- 保留现有三个字符串数组清单，其中条目全部为唯一平台名称；后续创建、洞悉、下载任务使用这些名称，不能用后续任务的新 ID 覆盖上传时映射。
- 下载恢复原始主文件名，保留下载的实际结果格式扩展名（例如 `学生_pn.txt` 的洞悉表格保存为 `学生_pn.xlsx`）；缺失映射的新平台名称必须报错，迁移的旧无映射名称保留明确的兼容路径。目标存在时不覆盖，待下载清单也不移除。
- `server/platform.js` 属于本任务，但不能修改 3.1 的 `server/routes.js`；向主代理报告需要在路由中按映射类型分组的集成接口，由 3.1 或后续整合处理。
- 新增专项测试文件；不要修改 `package.json`，由 3.3 统一接入测试。

## 要做的事

1. 在任务开始时保留每个文件的初始文件名，并在用户工作区新增一个 JSON 映射清单；清单至少保存 `platformName`、`originalName`、`type`、完整 `jobId`、`sequence` 和当前流程阶段所需的信息。
2. 上传流程将平台文件名改为新规则，通过环境变量接收 `RUYI_USER`、`RUYI_JOB_ID`；未设置这些变量时保留原有单机命名行为。
3. 创建人群、洞悉、下载和 `server/platform.js` 状态检查全部使用映射中的平台名称，不再根据初始文件名猜测平台对象。
4. 下载成功后按映射把结果保存为初始文件名；出现目标文件已存在、映射缺失或恢复后不安全的文件名时停止并给出中文错误，不覆盖已有结果。
5. 同一上传任务涉及的全部文件在上传前检查初始文件名重复；发现重复时一次性列出重复名称并停止任务，不能只检查某个 multipart 请求或静默改名。
6. 保持现有 JSON 清单的兼容读取，避免无关的数据库或前端改动；对旧的无映射清单提供明确的兼容或错误提示。

## 约束

- 不修改已有数据库迁移，不引入新依赖，不读取或修改真实 `upload/` 数据文件。
- 不把初始文件名、文件内容或登录凭证写入操作日志之外的敏感位置；日志中只记录必要的文件名摘要。
- 不能通过字符串拼接路径绕过用户工作区；所有文件名必须使用 `path.basename` 和现有安全校验。

## 测试

- 为命名、短任务 ID、30 字符上限、序号唯一性、重复初始文件名、映射读写和下载恢复补充 Node `assert` 测试。
- 测试旧单机模式没有 `RUYI_USER`/`RUYI_JOB_ID` 时仍使用原有命名逻辑。
- 运行 `npm test`，并在不启动浏览器的情况下覆盖上传前检查和下载目标路径保护。

## 完成标准

- 平台名称不包含初始文件名且在单个任务中唯一。
- 全流程只依赖映射后的平台名称，下载结果恢复为初始文件名且不会覆盖已有文件。
- 任务范围内测试通过，并列出未能在离线环境验证的平台页面假设。
