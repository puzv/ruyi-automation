# 任务 3.1：用户工作区与任务隔离

先阅读 `AGENTS.md`、`docs/HANDOFF.md`、`docs/REFACTOR_PLAN.md`，以及 `config.js`、`server/workspace.js`、`server/jobs.js`、`server/state.js`、`server/routes.js`、`server/audit-actions.js` 和现有服务端测试。

## 目标

阶段 3 不新增文件清单数据库表。每个登录用户使用独立目录 `<数据根目录>/users/<用户名>/`，目录内继续保留现有 `raw/`、`idfa/`、`oaid/`、`pn/`、`result/` 和 JSON 清单结构。

## 要做的事

1. 增加服务端工作区解析能力：从 `request.user.username` 得到用户目录，用户名已由登录规则限制为安全字符；路径必须由服务端计算，不能接受前端传入的路径。
2. 将 `/api/status`、`/api/import-folder`、`/api/platform-status` 的文件读取和写入改为当前用户目录；保持 `auth: false` 的旧测试可通过，并允许测试显式提供工作区。
3. `POST /api/run/:task` 启动任务时传入当前用户工作区、`RUYI_USER` 和服务端任务 ID（`RUYI_JOB_ID`）；`config.js` 继续支持脚本直接运行时的旧单机行为。
4. 为内存任务记录保存 `userId`、`username` 和任务 ID；同一用户已有运行中任务时返回 409，浏览器 Profile 仍然全局只允许一个运行中任务。
5. `GET /api/jobs/:id` 只允许任务所属用户查看，其他用户统一按任务不存在返回 404；释放 Profile、登录检查等全局互斥行为保持不变。
6. `job.finish` 审计记录继续使用启动任务用户和原始 requestId，任务环境变量不能写入操作日志。

## 集成约定（负责人确认后的补充）

- 服务端沿用 `config.uploadRoot` 作为数据根目录（默认项目的 `upload/`，可由 `RUYI_UPLOAD_DIR` 覆盖）；认证用户目录为 `<root>/users/<username>/`。不新增第二个含义重叠的根目录变量。
- 认证模式导入应保留原文件名，写入 `raw/<导入唯一标识>/<文件序号>/<原文件名>`；跨请求和同一请求里的同名文件都不能覆盖或被静默改名。3.2 在整个上传任务开始前递归检查所有待上传文件并提示重复。`auth: false` 旧测试保留原平铺导入兼容行为。
- 状态统计递归统计 raw 中的待上传文件；其他类型目录只统计待上传层，不统计 done。不得跟随符号链接到工作区外。
- 认证用户运行任务时必须先创建完整目录；同一用户任务运行期间拒绝继续导入，避免任务文件集合在预检后改变。
- `startJob` 通过可选参数 `{ user, uploadDir, onFinish }` 接收身份和目录；由服务端生成具有足够随机性的唯一任务 ID，再以 `RUYI_JOB_ID` 传入子进程。
- 全局 Profile 释放不能让 B 终止 A 的任务或返回 A 的任务 ID；有其他用户任务正在运行时普通用户请求释放应返回不泄露身份的 409，管理员可以释放，但返回的任务 ID 也必须按当前用户过滤。避免扩大到阶段 4 的 Profile 登录态重构。
- 新增专项测试文件；`package.json` 的测试入口统一由 3.3 整合，避免多个实现同时修改。

## 约束

- 不修改已有迁移文件，不新增数据库表，不读取或修改 `upload/` 下数据文件。
- 不改变任务脚本的工作目录语义；脚本收到的 `RUYI_UPLOAD_DIR` 必须是用户实际工作区。
- 不改变前端 API 返回字段，错误提示保持中文。
- 不允许把用户路径、Cookie、登录态或密码写入日志。

## 测试

- 扩展服务端路由测试：两个用户的状态和导入目录互不可见，用户 A 不能读取用户 B 的任务，用户级并发和全局浏览器并发分别返回正确的 409/404。
- 测试 `startJob` 的子进程环境包含用户工作区、`RUYI_USER` 和 `RUYI_JOB_ID`，并覆盖任务结束回调。
- 运行 `npm test`；数据库测试仍只使用现有阶段 2 测试库配置。

## 完成标准

- 服务端所有阶段 3 指定接口按用户隔离，任务环境和任务查询归属正确。
- 现有单机脚本在未设置用户变量时行为不变。
- 任务说明范围内的测试通过，并列出实际改动文件。
