# 7.2 Workspace 布局部署构建适配

## 目标
负责人已授权目录重构，应用迁移代理负责 apps/packages；部署仓库 /Users/getui/playwright-upload-deploy 同步支持新布局。只适配构建，不发布、不操作线上集群。阶段仍单副本、内嵌 Worker、桌面同源转发。

## 稳定接口
- 根 package.json workspaces apps/*、packages/*；唯一根 package-lock.json。
- 五包 @ruyi/web、@ruyi/server、@ruyi/worker、@ruyi/automation、@ruyi/shared，各有 package.json，Node CommonJS、web ESM。
- API 入口 apps/server/src/main.js；Worker apps/worker/src/main.js；前端 apps/web/src + index.html + vite.config.js。
- 自动化 packages/automation/*.js 及 lib/（以最终实际代码为准）；shared 中配置与 runtime；db/、scripts/ 保留根目录。
- npm start、npm run worker、npm run build:web 根命令保留，.env/缓存/数据根目录不变。

## 实施边界
- 只改部署仓库的 Dockerfile、Dockerfile.desktop、必要新增 Dockerfile.workspace、scripts/build-context.js、test/container-preparation.test.js、README.md、DESKTOP.md；主代理若需新增目录说明由代理报告。
- 新构建使用统一 root npm ci，复制五包 manifests 做缓存，再源码，再 npm run build:web。不可升级基础镜像或依赖；保留桌面监督/信号、pwuser、5173、浏览器路径和 apt 已验证配置。
- build-context 按选中的源码清单判别旧/新布局，仍支持旧 Git ref 构建；新旧所需文件分别校验，不能尝试不存在的 COPY。必要时添加独立 workspace Dockerfile，旧 Dockerfile 保持 legacy。
- 扩展安全白名单前仍先屏蔽敏感名/目录、拒绝符号链接；只允许具体五包源码与 manifest，绝不能打入数据/环境/登录态/node_modules/dist。禁止读取任何真实敏感文件。
- 不改 K8s 的镜像标签、资源、Secret、Worker 开关；不启动 Docker build/push，不安装依赖、不浏览器、不提交、无下级代理。
- 离线 fake Docker 测试需覆盖旧/新 ref、worktree，manifest和入口缺失、路径/符号链接/敏感数据过滤，保留已有测试。
- 应用迁移尚在进行，新 layout dry-run 等其可用后再做；可用临时假仓库检验，不执行 git commit（可用git plumbing造对象）。

## 验收
代理报告实际文件/离线测试。主代理审查所有 diff、独立离线测试和新布局 dry-run、实际本地镜像构建；不自动发布。部署仓库所有原先文件未跟踪，禁止误认为由本任务新增而删除。
