# 7.1 扫码登录修复（真实验收发现）

在 7.0 基础上修改，不新增依赖、不改迁移。

## 问题（Claude 用真实浏览器复现并定位）

验收账号已有**仍然有效**的平台登录态时点「扫码登录」：
1. `sessions.js` 会先把已保存的登录态加载进浏览器上下文（这是对的）。所以打开如翼后，页面直接是业务页面，或者正处于跳转中，**根本不会出现 `sso.e.qq.com` 登录页**。
2. `qr.js` 的 `waitForQrLogin` 在 `pageLooksLoggedIn` 返回 false 时立即调用 `selectMethod`。此时页面可能仍在跳转，或者已经是业务页面，`getByText('微信账号登录')` 等待 10 秒超时后抛出异常，被 `run()` 的 catch 捕获，会话直接 `failed`，提示「平台登录失败，请重新尝试」。
3. 失败前 `session.qr` 已被设为 `{ state: 'waiting', image: null, updatedAt }`，前端据此拼出图片地址，但图片接口返回 404，于是页面显示破图「微信登录二维码」。此时点 QQ，`switchMethod` 因 `qrPage` 尚未就绪也返回 409。

真实日志：`locator.click: Timeout 10000ms exceeded. waiting for getByText('微信账号登录', { exact: true })`。

## 修改要求

### 1. `waitForQrLogin`（如翼阶段）

- 打开目标地址后，**先等待页面稳定再判断**：最多轮询 20 秒，每轮检查两件事——
  - `pageLooksLoggedIn` 为真，并稳定 3 秒 → 已登录，**跳过扫码**，直接返回 true（`session.qr` 保持 null，`message` 为「已有有效登录，正在确认」）；
  - `ops.isLoginPage(page)` 为真 → 进入扫码流程。
- 20 秒内两者都不满足时，重新打开一次目标地址再判断；仍不满足则以 `failed` 结束，提示「无法打开平台登录页，请稍后重试或改用远程桌面登录」。
- 进入扫码流程后，`selectMethod` 失败**不得**导致会话结束：捕获异常，下一轮再试。连续 10 次失败后再以 `failed` 结束，提示同上。
- 循环中如果页面从登录页跳回业务页（例如在别处已完成登录），按已登录处理。

### 2. `session.qr` 只在真正截到图后对外暴露

- 在第一次 `readQr` 返回图片前，`publicSession` 的 `qr` 为 null，`message` 为「正在准备登录二维码」。
- 前端：`qr` 为 null 且会话为 `waiting` 时显示「正在准备二维码…」占位，不渲染 `<img>`。`qr` 存在时才显示切换按钮和图片。图片 `onerror` 时隐藏图片并显示「二维码加载中…」，不显示破图。
- `switchMethod` 在二维码尚未就绪时返回 409，提示「二维码准备中，请稍后再切换」。

### 3. 测试（`test/platform-login.test.js` 及 `test/platform-login-qr.test.js`）

使用假浏览器，覆盖以下场景：
- 已有有效登录态：打开即为业务页 → 不调用 `selectMethod`，不产生 `qr`，两站复查通过后成功保存；
- 页面先短暂停留在业务地址（未登录），再跳到登录页 → 正常进入扫码；
- `selectMethod` 前 2 次抛异常、第 3 次成功 → 会话继续，不失败；
- 连续 10 次失败 → `failed`，且提示文案正确；
- `qr` 在首次截图前为 null；
- 前端：`waiting` 且无 `qr` 时显示占位，不渲染图片。
