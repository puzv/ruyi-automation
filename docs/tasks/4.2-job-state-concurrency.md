# 任务 4.2：任务按用户加载登录态，放开并发

先阅读 `AGENTS.md`（“登录态”一节）、`docs/REFACTOR_PLAN.md` 的“阶段 4 的具体决定”、4.1 完成的 `server/platform-state/`、`server/repos/platform-states.js`，以及 `lib/browser.js`、`lib/preflight.js`、`config.js`、`server/jobs.js`、`server/routes.js`、`server/platform.js`、`server/state.js`、`server/audit-actions.js`。

## 背景
现在所有任务共用一个浏览器 Profile（`ruyi-profile/`），所以全局只能运行一个任务。4.1 已经能把每个用户的平台登录态（storageState）加密存库。本任务让每个任务使用**启动它的用户自己的登录态**，各自启动独立浏览器，因此不同用户可以同时运行任务。

`lib/browser.js` 已经支持 `RUYI_STATE_FILE`：设置后每次启动全新浏览器并加载该文件，关闭时仅在仍处于业务页面时回写。脚本经 `spawnSync` 启动的子脚本会继承环境变量，无需修改各个脚本。

## 要做的事

### 1. `lib/browser.js`
- `launchBrowser(options)` 支持 `options.storageState`（对象）：用它启动全新浏览器，不读写任何文件，也不受 `RUYI_STATE_FILE` 影响。这类上下文在 `closeBrowserContext` 中只关闭浏览器，**不回写**（用 Symbol 或 WeakSet 标记）。
- `RUYI_STATE_FILE` 模式下，关闭时如果页面停在登录页（`sso.e.qq.com` 或路径含 `/login`），在 `${stateFile}.logged-out` 写一个空的标记文件（权限 600），供服务端判断“登录已过期”。是否回写的现有规则不变。
- 导出 `saveRefreshedState`（或拆出一个纯函数）以便不启动浏览器就能测试上述判断：测试中用假的 context（`pages()` 返回带 `url()`、`isClosed()` 的对象，`storageState()` 写文件）。

### 2. 服务端启动任务（`server/jobs.js`、`server/routes.js`）
认证模式（`req.user` 存在）下 `POST /api/run/:task`：
1. 用 `loadUserState(app.db, user.id, app.stateKeys)` 读取登录态。没有登录态、已过期或解密失败时返回 409 `{ ok: false, code: 'PLATFORM_LOGIN_REQUIRED', message: '请先完成平台登录' }`，不启动任务（这次拒绝也照常记入 `job.start` 失败记录）。
2. 为本次任务创建临时目录：`fs.mkdtempSync(path.join(os.tmpdir(), 'ruyi-state-'))`，权限 700；写入 `state.json`（权限 600，`flag: 'wx'`）。用 `RUYI_STATE_FILE` 传给子进程。
3. 任务结束时（`onFinish` 之前，或者在 `jobs.js` 里统一处理）：
   - 若存在 `state.json.logged-out` 标记：`markExpired(db, { userId, expectedVersion })`，并写一条操作记录 `platform.state_expired`（`result='success'`，`detail.jobId`）
   - 否则若 `state.json` 内容与启动时写入的内容不同（比较 SHA-256）：`storeRefreshedState(db, userId, expectedVersion, 新对象, keys)`；返回 false（版本已变化，比如用户刚重新登录）时**不覆盖**，只在服务日志记一行
   - 内容相同则什么都不做
   - 最后**无论成功与否**删除整个临时目录（`fs.rmSync(dir, { recursive: true, force: true })`）
   - 读取或解析新文件失败时只记服务日志，不影响任务结束流程
4. `job.finish` 记录的 `detail` 增加 `stateRefreshed`、`stateExpired` 两个布尔值。
5. 任务对象保存 `expectedVersion`，**不得**把登录态明文、临时路径放进任务对象的可枚举字段（`GET /api/jobs/:id` 会把任务对象原样返回）。
6. 服务关闭时（`onClose`）删除所有仍存在的任务临时目录。

### 3. 并发规则（替换现有的全局单任务限制）
- 同一用户同时只能运行一个任务（已有，保留）：409 `当前用户已有任务正在运行，请等待完成`
- 全局同时运行的任务数上限 `RUYI_MAX_CONCURRENT_JOBS`（默认 2，读环境变量，非正整数时用默认值）：超出时 409 `服务器繁忙，当前已有 N 个任务在运行，请稍后再试`
- 认证模式下 `run/:task` **不再**因为 `profileReleaseRunning`、`profileProbeRunning`、`loginContexts`、`loginFlow` 拒绝（任务已不使用 Profile）。`auth: false` 模式保持原逻辑，旧测试不改。
- `POST /api/import-folder` 仍按“当前用户有任务运行时拒绝导入”处理。

### 4. 平台状态检查 `GET /api/platform-status`
- 认证模式下改用当前用户的登录态：`server/platform.js` 中 `inspectPlatformFiles`、`inspectAnalyseAudience`、`inspectInsightResults` 增加可选参数，用 `launchBrowser({ headless: state.headlessMode, storageState })` 启动浏览器。
- 没有可用登录态时返回 409 `PLATFORM_LOGIN_REQUIRED`（同上）。
- 互斥改为按用户：同一用户的检查正在进行时 409 `平台状态检查正在进行，请稍后重试`；不再因为其他用户的任务或 Profile 状态拒绝。用 `state.platformProbes = new Set()` 记录正在检查的用户 ID。
- `auth: false` 模式保持原逻辑。

### 5. 操作记录与前端标签
- `web/src/labels.js` 增加 `platform.state_expired: '平台登录已过期'`。
- 前端运行任务收到 `PLATFORM_LOGIN_REQUIRED` 时，提示文字显示服务端 message 即可（4.5 会再改界面），本任务不改其他前端代码。

## 测试 `test/job-state.test.js`（数据库测试，`ruyi_test`，保护与清理同 `test/platform-state.test.js`；加入 `test:all`）
用假的 `spawn`（可控的 EventEmitter，带 `stdout`/`stderr`/`pid`，记录收到的 `env`），**不得启动浏览器或真实脚本**：
- 没有登录态时 `run/upload` 返回 409 且 `code === 'PLATFORM_LOGIN_REQUIRED'`，没有调用 spawn
- 有登录态时：子进程 env 中 `RUYI_STATE_FILE` 指向的文件存在、权限 600、所在目录权限 700、内容等于存入的伪造 storageState；env 中没有登录态明文的其他副本
- 子进程结束且文件未改动：数据库 `version` 不变，临时目录已删除
- 子进程改写了文件（模拟回写）后结束：`version + 1`，解密后等于新内容，`job.finish` 的 `detail.stateRefreshed === true`
- 子进程留下 `.logged-out` 标记：状态变为 `expired`，写入 `platform.state_expired` 记录，`GET /api/platform-state` 返回 `expired`
- 任务运行期间用户重新保存了登录态（version 变化）：结束时不覆盖新登录态
- 子进程非 0 退出、或 spawn 触发 `error` 事件：临时目录同样被删除
- `GET /api/jobs/:id` 的响应 JSON 不包含 `RUYI_STATE_FILE`、临时目录路径、伪造 cookie 的值
- 并发：A、B 两个用户同时启动 → 都成功；A 再启动 → 409；`RUYI_MAX_CONCURRENT_JOBS=2` 时第三个用户 C → 409 服务器繁忙
- `lib/browser.js` 的回写判断：停在业务页 → 回写、无标记；停在 sso 页 → 不回写、有标记；无页面 → 不回写、无标记

已有测试（`test/server-isolation.test.js` 等）若因“全局单任务”规则变化而失败，按新规则更新断言，并在报告中逐条说明改了什么。
