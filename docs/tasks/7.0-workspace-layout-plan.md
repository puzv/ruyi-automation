# 7.0 apps/packages 目录迁移设计

## 已获确认
负责人要求采用 apps/web、apps/server、apps/worker、packages/automation、packages/shared 的结构，并明确保留 JavaScript、Kysely、现有路由，不引入 TypeScript、Pinia、vue-router。部署仍在独立仓库。

## 当前任务（只读）
读 AGENTS.md、package.json、config.js、server/worker、scripts、test 及部署仓库 Dockerfile/build-context，设计可执行迁移映射与风险列表。当前缺陷修复先完成，未经主代理通知不得写代码或移动文件。

## 必须解决的问题
- API 与 Worker 分离目录，默认 npm start 内嵌 Worker 的运行行为不变，npm run worker 仍可独立运行；允许依赖注入避免 apps 间循环依赖。
- 自动化及 lib 移入 packages/automation；共享配置/根路径/枚举归 packages/shared，只抽取确实共享的内容；Node 保持 CommonJS，Vue ESM。
- workspace package.json、根 scripts、lockfile、本地 node_modules 与 web 依赖迁移由主代理管理安装，不让子代理执行 npm install/ci。
- 数据库现有迁移绝不能修改内容；db/ 可先保留根目录集中管理，或提出迁移方案交主代理选择。真实 .env、state-test.json、ruyi-profile、upload 都必须原地不动，不可读取，默认路径必须仍指向原仓库根，浏览器缓存路径同理。
- scripts 中运维工具保持根 scripts/；测试和生产启动路径都要适配，不能只加大量旧路径转发壳而保留双份实现。
- 独立部署仓库需兼容新 workspace 构建（同时保留旧 Git ref 构建能力），白名单依然不能放入任何敏感文件。
- 已有未提交变更必须完整保留。仅读取允许的源码，禁止递归读取数据目录或环境文件。
