# 重构计划

目标：把单人本地工具改造成部署在 K8s、多人使用、数据按用户隔离、有操作记录的平台。

分工：Claude Code 负责规划、拆分任务、审查与验收；Codex 负责按任务说明编写代码；
每完成一个阶段，由项目负责人亲自验收后再进入下一阶段。

## 已确定的技术决定
| 项目 | 决定 |
|---|---|
| 后端 | Node.js + Fastify，CommonJS JavaScript，放在 `server/` |
| 前端 | Vue 3 + Vite，保留在 `web/`，只负责页面；开发时代理 `/api` 到后端 |
| 自动化脚本 | 保留现有 Playwright 脚本，后续阶段再改为可调用的函数 |
| 数据库 | 远程共享库 `bsg_dw`（MySQL 5.7），Kysely，表名前缀 `ruyi_` |
| 平台登录态 | storageState，AES-256-GCM 加密存入 `ruyi_platform_states` |
| 本系统登录 | 账号密码（bcrypt）+ 服务端会话 `ruyi_user_sessions` + httpOnly Cookie |

## 阶段

### 阶段 1：后端独立（功能不变）
把 `web/vite.config.js` 里的 API 拆成独立的 Fastify 服务，前端改为生产构建，由后端统一提供。
- 1.1 搭建 `server/`：Fastify 启动、提供 `web/dist` 静态文件、`/api/health`、npm 脚本
- 1.2 逐个迁移现有 10 个接口，路径、请求和返回格式保持不变
- 1.3 `web/vite.config.js` 只保留 Vue 插件和开发代理；清理 `RUYI_DEBUG_NAV` 诊断代码；更新 README
- 1.4 接口测试
- **验收**：构建并启动后，网页的状态显示、导入文件、运行任务、登录检测与改造前一致

### 阶段 2：用户登录与操作记录
- 用户登录 / 退出 / 修改密码，会话校验，登录失败锁定
- 命令行创建管理员；管理员创建、停用用户、重置密码
- 操作记录中间件；“我的操作记录”和管理员查询页面
- **验收**：未登录无法访问；不同用户登录后只看到自己的操作记录

### 阶段 3：用户数据隔离
- 每个用户独立目录 `/data/users/<用户名>/`；平台文件名加用户名前缀
- 任务状态按用户区分；同一用户同时只运行一个任务
- **验收**：两个用户互相看不到对方的文件、任务和结果

### 阶段 4：平台登录态改造
- 登录态加密存库；任务按用户加载登录态；过期检测与提醒
- 临时登录桌面（按需分配，经后端鉴权访问），替换原 Profile 登录流程
- **验收**：用户在网页内完成平台登录，之后运行任务无需 Profile

### 阶段 5：任务队列与 Worker
- 任务入 `ruyi_jobs` 表，Worker 独立进程认领执行；人群文件流水线状态入表
- **验收**：重启服务不丢任务记录；多人任务排队执行

### 阶段 6：部署
- 更新 Dockerfile 与 K8s 配置（API、Worker、登录桌面、Secret、Ingress）
- **验收**：在开发网 K8s 上完成以上全部验收项
