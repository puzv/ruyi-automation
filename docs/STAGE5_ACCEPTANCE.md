# 阶段 5A 验收清单（任务队列）

写给：项目负责人。可以和 `docs/STAGE3-4_ACCEPTANCE.md` 一起做；需要平台登录态才能真正运行任务。

## 准备

在新开的终端里：

```bash
cd ~/playwright-upload
npm run build:web
npm start
```

启动方式和以前一样，后台的 Worker 会随 `npm start` 一起运行。本地开发库 `ruyi_dev` 已经建好任务表，不需要额外操作。

## 验收步骤

1. 登录工作台，点“上传文件”。提示先显示“即将开始”或“排队中”，随后变为“运行中”，日志框实时滚动输出。
2. 任务运行中**刷新页面**：任务状态和日志自动恢复显示。
3. 任务结束后，日志框下方有“查看完整日志”，点开能看到完整输出。
4. 侧边栏进入“我的任务”：能看到刚才的任务，以及提交时间、状态、耗时。
5. **排队**：连续点“创建人群”和“人群洞悉”。第二个任务显示“排队中”，等第一个结束后自动开始。
6. **取消**：在“我的任务”里对排队中的任务点“取消”，状态变为“已取消”，这个任务不会被执行。
7. **重启不丢**：有任务运行时，在终端按 `Ctrl+C` 停止服务，再运行 `npm start`。重新打开“我的任务”：运行中的任务显示“已中断”，以前的任务记录都还在。
8. **多人**：另一个用户同时提交任务，两个人的任务能同时运行。第三个人提交时显示排队位置，前面有空位后自动开始（同时运行上限默认是 2）。
9. 管理员进入“全部任务”：能看到所有人的任务，可以按用户名和状态筛选；普通用户看不到这个入口。

## 行为变化

- 满员时不再提示“服务器繁忙”，改为排队。每人最多同时排队或运行 5 个任务。
- 同一个用户的任务会依次执行，不会同时执行。
- 服务重启时正在运行的任务会中断，状态显示“已中断”，需要手动重新运行；排队中的任务不受影响。
- 任务日志保存在 `upload/users/<用户名>/logs/` 下。
