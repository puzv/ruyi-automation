# 阶段 3 + 阶段 4 合并验收清单

写给：项目负责人。阶段 3（用户数据隔离）和阶段 4（平台登录态改造）一起验收。需要一个可以登录的如翼 / DataNexus 账号。

## 准备

在一个新开的终端里执行（不要沿用设置过 `RUYI_STATE_FILE` 的终端）：

```bash
cd ~/playwright-upload
npm install
npm --prefix web install
npm run build:web
npm start
```

打开 http://127.0.0.1:5173 。本机运行时，平台登录窗口会直接弹在这台 Mac 上（这是“本机模式”）；部署到 K8s 后会改为在网页里显示远程桌面（阶段 6 验证）。

用户名现在限制为 3–12 位。已有的 `puzw`、`pzw` 账号不受影响。

## 一、平台登录（阶段 4）

1. 用 `pzw` 登录。侧边栏显示“需要平台登录”；工作台右上角不再有“释放 Profile”按钮。
2. 不登录平台，直接点“上传文件” → 提示“请先完成平台登录”，并有跳转链接。
3. 进入“平台登录”页，点“开始登录”：
   - Mac 上弹出一个浏览器窗口，打开如翼登录页；网页上显示“如翼：等待登录”和倒计时
   - 在弹出的窗口里扫码登录如翼 → 网页显示如翼已登录，窗口自动打开 DataNexus
   - 登录 DataNexus → 网页显示“两个平台登录成功”，弹出的窗口自动关闭
4. 回到工作台，侧边栏显示“平台已登录”，鼠标悬停可看到预计过期时间。
5. 再次进入“平台登录”页 → 显示登录时间和预计过期时间（通常约 39～47 小时）。
6. “我的操作记录”里有“开始平台登录”和“平台登录（成功）”两条。

## 二、业务流程（阶段 3 + 4）

用一小份测试文件，文件名包含 `idfa`、`oaid` 或 `pn`，格式 `.txt` / `.csv`。

7. 导入文件 → 待上传数量增加。
8. 依次运行 上传 → 创建人群 → 人群洞悉 → 下载结果，每一步都成功。
9. 在如翼 / DataNexus 平台上检查名称：形如 `pzw_pn_1a2b3c4d_1`（用户名、类型、任务短串、序号），不包含原始文件名。
10. 下载结果保存在 `upload/users/pzw/result/`，文件名恢复为原始文件名（扩展名为实际结果格式，例如 `.xlsx`）。
11. 任务结束后，“平台登录”页的“最近刷新时间”更新（任务会把续期后的登录态写回）。

## 三、多用户隔离（阶段 3）

12. 用管理员 `puzw` 新建一个普通用户（例如 `qa1`），在无痕窗口用它登录并完成首次改密。
13. `qa1` 看不到 `pzw` 的待处理数量和文件；`qa1` 的侧边栏显示“需要平台登录”（登录态按人隔离）。
14. `qa1` 也完成平台登录（可以用同一个如翼账号）。两个用户同时各点一个任务 → 两个任务能同时运行；同一个用户连点两次 → 第二次提示“当前用户已有任务正在运行”。
15. `qa1` 在“我的操作记录”里只看到自己的记录；`puzw` 的“全部操作记录”能看到两人的记录。

## 四、清理

16. 在“平台登录”页点“清除登录态” → 状态变为“已过期”，运行任务会再次提示需要平台登录。
17. 验收通过后，可以删除旧的 `ruyi-profile/` 目录（新流程不再使用它；命令行单机脚本仍可在不设置 `RUYI_STATE_FILE` 时使用它，如果你不再用命令行，就可以删）。

## 已知限制

- 本机模式下，登录窗口在运行服务的那台电脑上弹出；别人通过网络访问你的服务时，他们看不到这个窗口。这个问题在部署到 K8s（远程桌面模式）后解决。
- 同时最多 2 个任务运行（可用 `RUYI_MAX_CONCURRENT_JOBS` 调整）；本机模式下同时最多 2 人在登录平台，远程桌面模式下同时 1 人。
- 已迁移的 `pzw` 历史数据继续使用旧的平台名称，新任务才使用新命名。
